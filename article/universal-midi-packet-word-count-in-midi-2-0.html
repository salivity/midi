Universal MIDI Packet Word Count in MIDI 2.0

The Universal MIDI Packet (UMP) is the core data format introduced in the MIDI 2.0 specification, designed to support both legacy MIDI 1.0 messages and modern, high-resolution MIDI 2.0 protocols. An individual Universal MIDI Packet does not have a single fixed size; instead, it consists of one to four 32-bit words (ranging from 32 bits to 128 bits in total length). The exact word count is determined dynamically by the packet's Message Type, allowing devices to optimize bandwidth and process messages efficiently across modern digital interfaces.

Determining Packet Length via the Message Type

Every Universal MIDI Packet begins with a 32-bit header word. The most significant four bits (bits 28 to 31) of this initial word define the Message Type (MT). The receiving device inspects these four bits to immediately determine the exact length of the incoming packet, ensuring proper framing and stream synchronization.

Depending on the Message Type, a UMP contains one of four possible lengths:

  • 1 Word (32 bits): Message Types 0x0, 0x1, and 0x2
  • 2 Words (64 bits): Message Types 0x3 and 0x4
  • 3 Words (96 bits): Reserved for future standardized definitions
  • 4 Words (128 bits): Message Types 0x5, 0xD, and 0xF

Word Counts by Message Category

1-Word Packets (32 bits)

Single-word packets are used for low-bandwidth, high-frequency, or legacy control operations:

  • Utility Messages (MT 0x0): Includes functions such as timestamps and clock pacing.
  • System Real-Time and System Common (MT 0x1): Transports standard transport and synchronization commands like Start, Stop, Continue, Active Sensing, and Song Position Pointer.
  • MIDI 1.0 Channel Voice (MT 0x2): Carries traditional MIDI 1.0 Channel Voice messages (Note On, Note Off, Control Change, Pitch Bend) framed within the UMP architecture.

2-Word Packets (64 bits)

Two-word packets provide the expanded bit depth required for expressive real-time performance and legacy data blocks:

  • Data Messages / 64-bit SysEx (MT 0x3): Transports traditional MIDI System Exclusive 7-bit data across multiple sequential 64-bit packets.
  • MIDI 2.0 Channel Voice (MT 0x4): Carries native MIDI 2.0 commands, enabling 32-bit high-resolution velocity, 32-bit control change values, per-note pitch bend, and individual note management.

3-Word Packets (96 bits)

The 96-bit format is recognized by the framing specification to accommodate future expansion where 64 bits is insufficient and 128 bits produces unnecessary overhead.

4-Word Packets (128 bits)

Four-word packets are used for complex payloads, extended configuration, and streaming metadata:

  • Extended Data / 128-bit SysEx (MT 0x5): Supports mixed-data sets and 8-bit System Exclusive streams.
  • Flex Data Messages (MT 0xD): Transports non-performance text, metadata, lyrics, and configuration data alongside performance streams.
  • Stream Messages (MT 0xF): Handles endpoint discovery, stream configuration, function blocks, and protocol negotiation between connected endpoints.

Summary

An individual Universal MIDI Packet in MIDI 2.0 comprises 1, 2, 3, or 4 32-bit words (32, 64, 96, or 128 bits). By standardizing all communication into multiples of 32-bit boundaries, the MIDI 2.0 specification enables fast memory alignment for modern 32-bit and 64-bit processors while preserving backward compatibility with legacy MIDI architectures.
