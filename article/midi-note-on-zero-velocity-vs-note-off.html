MIDI Note On Zero Velocity vs Note Off

In the MIDI 1.0 specification, transmitting a Note On command with a velocity value of zero functionally serves as a Note Off command. This design choice was engineered primarily to optimize data transmission over low-bandwidth serial connections by leveraging a feature called "Running Status." Modern digital audio workstations and hardware synthesizers treat a Note On message with zero velocity as identical to a dedicated Note Off message, initiating the release stage of a sound without requiring an explicit change in the MIDI status byte.

The Structure of MIDI Note Messages

Standard MIDI channel voice messages for triggering and releasing notes are composed of three bytes:

  1. Status Byte: Identifies the message type and the MIDI channel (e.g., 0x90 represents a Note On event on Channel 1, while 0x80 represents a Note Off event on Channel 1).
  2. Data Byte 1: Identifies the MIDI note number (0–127).
  3. Data Byte 2: Identifies the velocity value (0–127).

Under standard conditions, playing a note sends 0x90 [Note Number] [Velocity], and releasing that key sends 0x80 [Note Number] [Release Velocity].

Bandwidth Optimization via Running Status

The original MIDI 1.0 standard operates over a 31.25 kbaud serial interface, which is susceptible to latency and jitter when large volumes of data are transmitted simultaneously. To conserve bandwidth, the specification introduces Running Status.

Running Status permits a MIDI transmitter to omit the status byte if subsequent messages share the same status type and channel. If a keyboard constantly switches between Note On (0x90) and Note Off (0x80), every action requires transmitting the full three bytes because the status byte changes with every press and release.

By defining a Note On message with a velocity of zero (0x90 [Note Number] 0x00) as a functional release command, the transmitter never needs to leave the Note On status. Once the initial 0x90 byte is sent, all subsequent note presses and releases require only two bytes—the note number and the velocity—reducing data overhead by roughly 33% during dense musical passages.

Functional Behavior at the Receiver

When a MIDI receiver parses incoming data, it evaluates both the status byte and the velocity byte:

  • If it encounters a dedicated Note Off status byte (0x80), it ends the specified note immediately.
  • If it encounters a Note On status byte (0x90) with a velocity greater than zero, it triggers the note's attack phase.
  • If it encounters a Note On status byte (0x90) where the velocity byte equals 0, internal logic automatically routes this to the note-ending handler.

In both termination scenarios, the sound generator enters the release stage of its amplitude envelope.

The Single Difference: Release Velocity

The only operational distinction between the two approaches involves release velocity (often called "note-off velocity"). A dedicated Note Off message (0x80) uses its second data byte to indicate how quickly the key was released, allowing compatible synthesizers to modulate the length or timbre of the sound's release tail. Because Note On with zero velocity fixes the velocity byte at zero to signal the release, it cannot carry variable release velocity data. However, because the vast majority of commercial MIDI controllers and sound engines do not utilize release velocity, Note On with zero velocity remains a standard implementation across the industry.
