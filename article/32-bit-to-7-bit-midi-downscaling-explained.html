32-Bit to 7-Bit MIDI Downscaling Explained

This article explains how modern MIDI translation systems convert high-resolution 32-bit controller data into the legacy 7-bit format used by standard MIDI 1.0 hardware. You will learn the mathematical principles behind this conversion, the primary methods of truncation and linear scaling, and how protocol converters manage data density without overwhelming legacy communication bandwidth.

The Numerical Difference

A standard MIDI 1.0 Control Change (CC) message represents values using a 7-bit unsigned integer, providing 128 discrete steps ranging from 0 to 127. In contrast, modern protocols—such as MIDI 2.0—utilize 32-bit resolution for property exchange and continuous controllers. A 32-bit unsigned integer offers 4,294,967,296 discrete values (0 to 4,294,967,295).

To make a 32-bit controller compatible with a 7-bit receiver, a downscaler must compress this multi-billion-step range into 128 discrete values while maintaining proportional accuracy.

Method 1: Bit-Shifting (Truncation)

The fastest and most computationally efficient method to downscale is bitwise right-shifting. Because the target format requires 7 bits, the downscaler isolates the 7 most significant bits (MSBs) of the 32-bit word and discards the remaining 25 least significant bits (LSBs).

In code or digital logic, this operation is expressed as:

7_bit_value = 32_bit_value >> 25

Because \(32 - 7 = 25\), shifting the binary data 25 places to the right moves the top 7 bits into the lowest positions (0 through 6) and clears out the rest.

  • Advantage: Requires virtually zero processor overhead, making it ideal for microcontrollers and hardware bridges.
  • Limitation: It performs an implicit floor operation, discarding fine-grained fractional movement without rounding to the nearest target value.

Method 2: Linear Ratio Scaling (Normalization)

Linear scaling preserves mathematical proportions more accurately by normalizing the 32-bit value to a range between 0.0 and 1.0, multiplying by the 7-bit maximum (127), and rounding to the nearest integer.

The formula is:

7_bit_value = round((32_bit_value / 4294967295) * 127)

In pure integer arithmetic to prevent floating-point overhead:

7_bit_value = ((32_bit_value * 127) + 2147483647) / 4294967295

  • Advantage: Correctly maps absolute minimum (\(0\)) to \(0\) and absolute maximum (\(4,294,967,295\)) to \(127\), distributing transition points symmetrically.
  • Limitation: Involves multiplication and division operations that require slightly more processing power than a basic bit-shift.

Official MIDI 2.0 Downscaling Standard

The MIDI Association specifies exact rules for downscaling MIDI 2.0 32-bit values to MIDI 1.0 messages. For standard 7-bit controllers, the specification dictates taking the top 7 bits directly (equivalent to value >> 25).

This simple bit-truncation standard ensures deterministic performance across all hardware manufacturers:

32-Bit Hex Range 32-Bit Decimal Range Resulting 7-Bit Value
0x00000000 – 0x01FFFFFF 0 – 33,554,431 0
0x02000000 – 0x03FFFFFF 33,554,432 – 67,108,863 1
... ... ...
0xFE000000 – 0xFFFFFFFF 4,261,412,864 – 4,294,967,295 127

Rate Limiting and Thinning

Downscaling involves more than reducing resolution; it also requires managing transmission speed. A 32-bit continuous controller stream often transmits updates at high frequencies over USB or Ethernet.

Legacy MIDI 1.0 operates via a 5-pin DIN serial connection limited to a baud rate of 31.25 kbps, which can handle roughly 1,000 standard CC messages per second. A hardware downscaler must therefore implement value filtering:

  1. State Tracking: The downscaler stores the previous 7-bit output value in memory.
  2. Change Evaluation: When a new 32-bit value arrives, it is downscaled. If the newly calculated 7-bit value matches the stored value, the message is discarded.
  3. Throttling: Only when the continuous input shifts enough to cross a 7-bit threshold is a new MIDI 1.0 message transmitted, preventing buffer overflows on older equipment.
