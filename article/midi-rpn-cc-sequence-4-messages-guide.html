MIDI RPN CC Sequence: 4 Messages Guide

This article provides a concise overview of executing a complete Registered Parameter Number (RPN) modification using the MIDI 1.0 specification. To adjust standard parameters such as pitch bend sensitivity, master fine tuning, or tuning program changes with full 14-bit resolution, a transmitter must output a precise sequence of four distinct Continuous Controller (CC) messages. These messages address the parameter address registers and subsequently transmit the coarse and fine data bytes to update the target device reliably.

1. Controller 101: RPN Most Significant Byte (MSB)

The sequence begins by specifying the high byte of the target parameter address.

  • CC Number: 101 (0x65)
  • Function: Sets the RPN MSB (coarse parameter selection).
  • Value Range: 0–127

2. Controller 100: RPN Least Significant Byte (LSB)

Immediately following the MSB, the receiving device requires the low byte of the target address to lock onto the specific registered parameter.

  • CC Number: 100 (0x64)
  • Function: Sets the RPN LSB (fine parameter selection).
  • Value Range: 0–127

3. Controller 6: Data Entry Most Significant Byte (MSB)

Once the parameter is selected via CC 101 and CC 100, the controller sends the primary coarse data value for the parameter.

  • CC Number: 6 (0x06)
  • Function: Sets the coarse value of the selected RPN.
  • Value Range: 0–127

4. Controller 38: Data Entry Least Significant Byte (LSB)

To complete the 14-bit resolution modification, the controller sends the fine data value. For parameters that only require 7-bit resolution (like basic pitch bend depth in semitones), this step is often optional, but a complete high-resolution RPN command requires this fourth distinct message.

  • CC Number: 38 (0x26)
  • Function: Sets the fine value of the selected RPN.
  • Value Range: 0–127

Best Practice: RPN Deselection (Null Parameter)

After sending the four-message sequence, standard practice dictates resetting the parameter pointers to prevent accidental parameter alterations from subsequent stray Data Entry commands. This is accomplished by sending value 127 (0x7F) to both CC 101 and CC 100, effectively engaging the "RPN Null" state.
