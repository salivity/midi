Converting Pitch Bend Curves to MIDI Polylines

Digital Audio Workstations (DAWs) bridge the gap between fluid, analog-style performance gestures and the rigid digital framework of MIDI by converting continuous pitch bend curves into stepped, editable polyline shapes. This transformation relies on mathematical sampling, data reduction algorithms, and vector quantization to balance visual clarity for the producer with the high-resolution event streams required by MIDI synthesizers. Understanding this pipeline explains how freehand curves are converted into manageable vector points and smooth pitch transitions.

Continuous Curves vs. Discrete MIDI

In modern DAW interfaces, users often draw smooth, mathematically continuous Bézier curves to modulate pitch. However, standard MIDI protocol does not support continuous analog functions; it processes discrete digital messages sent across specific time intervals. Pitch bend uses a high-resolution 14-bit system offering 16,384 discrete steps (-8,192 to +8,191) split into two 7-bit bytes (Most Significant Byte and Least Significant Byte). Consequently, any continuous line drawn on a display must be mapped onto this 14-bit grid along the timeline's Pulses Per Quarter Note (PPQ) resolution.

Temporal Sampling and Quantization

When a user draws a pitch curve, the DAW tracks the cursor's path across the screen coordinates and samples the position at regular temporal intervals determined by the project's internal clock or the audio buffer rate. The vertical coordinate maps to the target pitch value, while the horizontal coordinate maps to project time.

Because outputting 16,384 distinct values at maximum frequency would overwhelm the MIDI engine and create cluttered interfaces, DAWs quantize the time domain based on the active snap settings or a fixed sampling rate (typically every few milliseconds). Each sample point along the continuous visual curve is assigned the nearest corresponding 14-bit integer.

Polyline Conversion via Curve Simplification

To present the user with an editable "polyline" rather than thousands of individual vertical data bars, DAWs apply line-simplification algorithms. The most common method is an adaptation of the Ramer-Douglas-Peucker (RDP) algorithm.

  1. Baseline Creation: The algorithm draws an imaginary straight segment between the start and end points of a drawn curve.
  2. Deviation Measurement: It locates the point on the drawn curve furthest from this segment and calculates the perpendicular distance.
  3. Threshold Filtering (Tolerance): If this distance exceeds a predefined tolerance threshold, that point is marked as an essential node (anchor point). The process recursively evaluates sub-segments until all remaining curve deviations fall within the acceptable margin of error.
  4. Node Generation: The surviving coordinates become the editable vertices of the polyline.

Through this process, a freehand stroke consisting of thousands of individual mouse movements is reduced to a concise set of vector nodes connected by straight line segments or editable curve handles.

Event Interpolation and Playback

The polyline displayed in the DAW interface is a high-level vector representation, not the actual data transmitted to the sound engine. During playback, the DAW reads the vector polyline and performs real-time interpolation:

  • Vector Evaluation: The engine computes the mathematical slope between each anchor node.
  • Density Generation: For every tick on the timeline, the DAW calculates the exact expected pitch value along that slope.
  • Redundancy Stripping: To optimize processing, identical consecutive values are skipped. A new MIDI pitch bend message is generated only when the value changes to a new integer step on the 14-bit scale.

This two-tier architecture allows producers to edit a clean, minimal set of polyline points while the DAW generates the stepped, high-density 14-bit MIDI data stream required to prevent audible pitch stepping or "zipper noise" during playback.
