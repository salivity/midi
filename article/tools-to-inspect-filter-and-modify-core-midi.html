Tools to Inspect, Filter, and Modify CoreMIDI

Developing audio and MIDI software on Apple operating systems requires deep visibility into the CoreMIDI subsystem to diagnose latency, verify data integrity, and manipulate message payloads. This guide outlines the premier standalone applications, visual programming environments, and programmatic APIs used to inspect, filter, and modify real-time CoreMIDI packets on macOS and iOS.

Snoize MIDI Monitor

For real-time inspection, Snoize MIDI Monitor is the standard diagnostic utility on macOS. It acts as an open-source passive listener that intercepts incoming and outgoing CoreMIDI communication across physical hardware, network sessions, and virtual endpoints. Developers can view incoming messages chronologically with microsecond-level timestamps, examine raw hexadecimal values alongside human-readable decodes (such as Note On, Control Change, and System Exclusive data), and apply source-level filters to isolate specific endpoints during active debugging sessions.

Bome MIDI Translator Pro

When bidirectional manipulation and packet modification are required, Bome MIDI Translator Pro operates as an inline processing hub. The tool captures incoming CoreMIDI streams, runs them through user-defined routing logic, and outputs transformed packets to secondary virtual ports. Developers can remap Control Change numbers, scale velocity values, split incoming data across multiple MIDI channels, and translate incoming CoreMIDI events into completely different protocols, such as keystrokes, mouse actions, or custom SysEx strings.

Native CoreMIDI Services and Virtual Endpoints

For developers building internal testing harnesses or custom routing tools, Apple's native CoreMIDI framework provides the lowest-latency access to the packet stream. Using MIDIDestinationCreateWithBlock or MIDISourceCreate, developers can create virtual endpoints that act as native loopback devices. In modern macOS and iOS versions, CoreMIDI processes Universal MIDI Packets (UMP) and MIDI 2.0 data via MIDIEventList structures alongside legacy MIDIPacketList structures. By implementing a read block in Swift or Objective-C, a developer can inspect raw packet headers, discard messages that match specific filter predicates, alter byte payloads in memory, and retransmit the stream using MIDISend.

Max/MSP and Pure Data

Visual programming environments like Cycling '74 Max and Pure Data (Pd) provide flexible testbeds for prototyping CoreMIDI manipulation logic without compiling full applications. Using built-in objects such as midiin, midiselect, midiformat, and midiout, developers can break real-time CoreMIDI packets down to their raw status and data bytes. Arithmetic operations, conditional logic, and clock-sync routines can be applied visually in real time to filter noise, modify event timing, or adjust control parameter curves before routing the stream back to software instruments or DAWs.

AudioKit

AudioKit is an open-source Swift framework that abstracts the low-level C-based CoreMIDI API on iOS, iPadOS, and macOS. It provides built-in listener protocols and event handlers—such as MIDIListener—allowing developers to inspect incoming packets using clean Swift syntax. AudioKit simplifies the creation of real-time filters by exposing callbacks for notes, continuous controllers, and pitch bend changes, making it straightforward to transform packet data on the fly within native Apple ecosystem applications.
