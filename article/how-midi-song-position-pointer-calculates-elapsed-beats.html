How MIDI Song Position Pointer Calculates Elapsed Beats

A MIDI Song Position Pointer (SPP) message allows sequencers, drum machines, and digital audio workstations to maintain synchronization by communicating an exact playback location within a song. Rather than using absolute time like hours and seconds, SPP measures musical time relative to the beginning of a composition. This article explains how the SPP message uses a 14-bit binary value to represent elapsed musical time in sixteenth-note increments, how the MIDI protocol mathematically defines these intervals, and how receiving devices convert the data into bars and beats.

The Structure of the SPP Message

The Song Position Pointer is a MIDI System Common message consisting of a status byte followed by two data bytes:

  • Status Byte: 0xF2 (identifies the message as Song Position Pointer)
  • Data Byte 1: Least Significant Byte (LSB), containing 7 bits of data (values 0–127)
  • Data Byte 2: Most Significant Byte (MSB), containing 7 bits of data (values 0–127)

Because standard MIDI data bytes reserve the most significant bit (bit 7) to distinguish data from status bytes, each byte transmits 7 usable bits. When combined, the LSB and MSB form a single 14-bit unsigned integer ranging from 0 to 16,383:

\[\text{Song Position Value} = \text{LSB} + (\text{MSB} \times 128)\]

The Sixteenth-Note Unit

The MIDI 1.0 specification defines one unit of the SPP value as one "MIDI beat." In the context of SPP, a MIDI beat is fundamentally defined as six MIDI Clock pulses, which equals exactly one sixteenth note (a semiquaver).

Standard MIDI Timing Clock messages (0xF8) run at a fixed rate of 24 pulses per quarter note (PPQN). Dividing these 24 pulses across the subdivisions of a quarter note establishes the relationship:

  • 1 Quarter Note = 24 MIDI Clocks
  • 1 Eighth Note = 12 MIDI Clocks
  • 1 Sixteenth Note = 6 MIDI Clocks

Therefore, an SPP value of 1 indicates that 6 MIDI Clocks (one sixteenth note) have elapsed since the beginning of the song. An SPP value of 0 denotes the absolute start of the track (Measure 1, Beat 1, Tick 0).

With a maximum 14-bit integer of 16,383, the message can address up to 16,384 sixteenth notes. In standard 4/4 time, this provides enough range to cue playback up to 1,024 measures into a project.

Calculating Bars and Beats from SPP

Receiving devices translate the raw sixteenth-note count into traditional musical notation (bars, beats, and sixteenth-note subdivisions) based on the project's time signature.

In a standard 4/4 time signature:

  • 1 Beat (Quarter Note) = 4 Sixteenth Notes
  • 1 Bar (Measure) = 16 Sixteenth Notes

Given an arbitrary 14-bit SPP integer, a receiving device performs integer division and modulo operations to find the exact position:

  1. Completed Bars: \(\lfloor \text{SPP Value} / 16 \rfloor\)
  2. Current Bar: \(\lfloor \text{SPP Value} / 16 \rfloor + 1\)
  3. Remaining Sixteenth Notes in Bar: \(\text{SPP Value} \pmod{16}\)
  4. Beat within Bar: \(\lfloor (\text{SPP Value} \pmod{16}) / 4 \rfloor + 1\)
  5. Sixteenth Note within Beat: \((\text{SPP Value} \pmod{4}) + 1\)

Practical Example

To cue a slave device to the beginning of Measure 9, Beat 3 in 4/4 time:

  1. Calculate completed bars: 8 full bars have passed.
    \(8 \times 16 = 128 \text{ sixteenth notes}\)
  2. Calculate completed beats in the current bar: 2 quarter notes have passed.
    \(2 \times 4 = 8 \text{ sixteenth notes}\)
  3. Sum total sixteenth notes:
    \(128 + 8 = 136\)
  4. Split 136 into 7-bit LSB and MSB:
    • \(\text{MSB} = \lfloor 136 / 128 \rfloor = 1\)
    • \(\text{LSB} = 136 \pmod{128} = 8\)

The transmitting device sends the byte sequence 0xF2 0x08 0x01. The receiving device reconstructs the integer \((8 + (1 \times 128) = 136)\), advances its internal playback cursor by 136 sixteenth notes (or 816 MIDI clock ticks), and waits for a MIDI Continue (0xFB) message to resume playback in sync.
