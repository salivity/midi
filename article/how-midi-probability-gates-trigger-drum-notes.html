How MIDI Probability Gates Trigger Drum Notes

An algorithmic MIDI probability gate determines whether a sequenced drum note sounds during a loop iteration by comparing a user-defined threshold against a dynamically generated pseudo-random number. Instead of playing every programmed hit deterministically, the sequencer evaluates this condition in real time on each pass of the playhead. This computational check decides whether to transmit the MIDI Note-On message or discard it, introducing organic variation, syncopation, and generative behavior into repetitive drum patterns.

The Trigger Mechanism

When a drum sequencer reaches a step containing a note event with an assigned probability, the playback engine intercepts the standard execution flow. Rather than immediately passing the MIDI data directly to the output buffer, it routes the event through a logical conditional check.

This process follows a standardized sequence on every iteration of the loop:

  1. Parameter Readout: The sequencer identifies the target probability value assigned to the drum hit (commonly expressed as a percentage from 0% to 100%, or a normalized float from 0.0 to 1.0).
  2. Value Generation: The internal processing engine calls a Pseudo-Random Number Generator (PRNG) to generate an instantaneous value within the same operational range (e.g., 0.0 to 1.0).
  3. Threshold Comparison: The logic gate executes a simple relational comparison:
    • If Random Value < Probability Threshold, the gate opens.
    • If Random Value ≥ Probability Threshold, the gate remains closed.
  4. Message Transmission: If the gate opens, the engine transmits the MIDI Note-On message (complete with its defined pitch, velocity, and channel) to the synthesizer or sampler. If the gate remains closed, the Note-On message is dropped for that specific cycle.

Loop Independence and Seeding

On each repeat of the loop, the sequencer clock triggers the calculation anew. Because standard PRNG algorithms use high-resolution system timers or shifting mathematical seeds to generate numbers, the value generated for Step 4 on Loop Iteration 1 will be entirely independent of the value generated for Step 4 on Loop Iteration 2. A hi-hat set to a 75% probability has the exact same 3-in-4 chance of firing every time the playhead arrives at that step, regardless of whether it triggered during the previous pass.

Some modern sequencers offer "locked" or "seeded" probability modes. In these implementations, the PRNG uses a fixed seed value or a repeating pseudo-random sequence (such as a linear-feedback shift register). This forces the probability gate to make identical pass/fail decisions across successive loop cycles, creating a complex, evolving pattern that loops predictably rather than firing with pure randomness.

Voice Management and MIDI Cleanliness

To prevent MIDI errors, probability gates evaluate strictly on the Note-On phase. If the condition evaluates to true and a Note-On event is transmitted, the sequencer automatically schedules the corresponding Note-Off event to ensure the voice terminates correctly. If the probability gate drops the Note-On event, it also suppresses the corresponding Note-Off command, preventing orphaned messages, voice allocation errors, or stuck notes in downstream instruments.
