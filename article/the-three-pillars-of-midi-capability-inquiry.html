The Three Pillars of MIDI Capability Inquiry

MIDI Capability Inquiry (MIDI-CI) is an architectural framework designed to expand standard MIDI communication by enabling devices to discover each other's features and automatically negotiate advanced functionality. This article breaks down the three foundational pillars that constitute the MIDI-CI specification: Protocol Negotiation, Profile Configuration, and Property Exchange. Together, these three mechanisms establish backward compatibility with legacy MIDI gear while unlocking the high-resolution, bidirectional workflows defined in the MIDI 2.0 standard.

1. Protocol Negotiation

Protocol Negotiation is the discovery mechanism that determines which MIDI language two connected devices will use to communicate. When a connection is established, devices default to standard MIDI 1.0. Through Protocol Negotiation, the devices query each other to determine if both ends support the newer Universal MIDI Packet (UMP) format and MIDI 2.0 protocols. If both endpoints confirm support, they switch seamlessly to MIDI 2.0, gaining access to higher-resolution velocity, increased control change resolution, and expanded channel counts. If either device lacks MIDI 2.0 capabilities, the system safely remains on MIDI 1.0 without interrupting data flow.

2. Profile Configuration

Profile Configuration establishes standardized sets of functional rules for specific types of musical instruments and controllers. A "Profile" defines how a device responds to common controls, such as drawbars on an electric organ, articulations for an orchestral library, or specific synthesizer parameters. Instead of requiring users to manually map MIDI Continuous Controllers (CCs) for every distinct instrument, devices can enable an agreed-upon profile. Once active, the controller and sound generator align their parameter mappings automatically, guaranteeing consistent behavior across hardware and software from different manufacturers.

3. Property Exchange

Property Exchange provides a standardized method for devices to query and alter each other's internal configuration data, presets, and metadata. Built primarily on universal formats like JSON, Property Exchange allows a controller, computer, or digital audio workstation (DAW) to retrieve rich information from a connected hardware synthesizer or effect unit. This includes patch names, parameter names, current control values, device statistics, and even user-interface layout information. By transmitting this data over standard MIDI channels via System Exclusive messages, Property Exchange eliminates the need for proprietary editor software, enabling controllers to visually display and manage an external device's internal state directly.
