How MIDI-CI Queries Device Operational Profiles

MIDI Capability Inquiry (MIDI-CI) transforms musical instrument communication by allowing connected devices to automatically discover and negotiate features through bidirectional messaging. Central to this architecture is the Profile Configuration category, which enables two devices to query each other's operational profiles. These profiles define standardized sets of rules, controllers, and behaviors tailored for specific musical tasks, allowing devices to configure themselves dynamically without manual user intervention.

The Foundation of Bidirectional Discovery

Traditional MIDI communication is strictly unidirectional, meaning a controller sends messages without knowing the capabilities of the receiving sound generator. MIDI-CI operates over standard MIDI 1.0 or MIDI 2.0 transport layers using Universal System Exclusive (SysEx) messages to establish a two-way conversation. Once two devices connect and complete the initial discovery handshake to verify MIDI-CI support, they can begin querying each other's operational capabilities across three distinct categories: Protocol Negotiation, Profile Configuration, and Property Exchange.

The Profile Inquiry Process

The query of operational profiles follows a structured, step-by-step transaction between an Initiator and a Responder:

  1. Profile Inquiry Request: A device sends a Profile Inquiry message addressed to a specific MIDI channel or across the entire device (using standard broadcast identifiers). This message effectively asks the receiving device to list every profile it supports.
  2. Profile Inquiry Reply: The receiving device responds with a comprehensive list of all operational profiles it recognizes. This reply includes both standardized profiles defined by the MIDI Association and custom, manufacturer-specific profiles. For each profile listed, the device indicates whether the profile is currently active or inactive, as well as the specific channels on which the profile can operate.

Profile Structure and Identifiers

Operational profiles are represented by unique 5-byte identifiers:

  • Standard Profiles: Managed and registered by the MIDI Association. Examples include standard drawbar organ controls, specific piano behaviors, and microtonal tuning systems. Standard profiles ensure cross-brand compatibility, meaning a controller designed for organs will instantly map drawbars and switches correctly to a synthesizer running an organ profile.
  • Manufacturer Profiles: Defined by individual hardware or software developers for specialized, proprietary functions while still adhering to the standard MIDI-CI query structure.

Profile Activation and Dynamic State Negotiation

Querying available profiles is only the first phase; devices also use MIDI-CI to negotiate their operational states:

  • Activating Profiles: If the inquiring device determines that a compatible profile is available, it sends a Set Profile On message specifying the target profile identifier and the designated MIDI channel.
  • Deactivating Profiles: Similarly, devices can revert to standard MIDI behaviors by sending a Set Profile Off message.
  • Confirmation and Specificity: The receiving device replies with either a Profile Enabled or Profile Disabled notification. If a device cannot activate a profile—due to resource limitations or channel conflicts—it responds with a Profile Specific Data or a rejection message, ensuring both devices maintain an identical understanding of the current operational state.

Through this automated query-and-response loop, MIDI-CI allows connected synthesizers, controllers, and software to establish coherent parameter mappings and feature sets instantly upon connection.
