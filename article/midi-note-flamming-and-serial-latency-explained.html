MIDI Note Flamming and Serial Latency Explained

MIDI note flamming is an audible artifact where notes meant to sound simultaneously are played back with slight, sequential delays, resembling a drummer's "flam." This article explains what MIDI flamming is, breaks down the technical limitations of traditional 5-pin DIN serial cables, and details the mathematical reasons why transmitting a ten-note chord over a serial connection inherently produces perceptible timing offsets between notes.

What Is MIDI Note Flamming?

In acoustic percussion, a "flam" consists of two drum strikes played very close together, creating a smeared or thickened transient rather than a single distinct hit. In digital music production, "MIDI note flamming" describes an unwanted, staggered playback of notes that share the exact same start time in a sequence.

When a keyboard player strikes a chord or a sequencer triggers multiple voices at the same instant, all notes are intended to sound concurrently. However, if those notes are separated by micro-delays during transmission, the chord's attack loses its punch. Instead of a crisp, unified hit, the notes smear across several milliseconds, which is especially noticeable on instruments with sharp, instantaneous attacks such as acoustic pianos, clavichords, or synthesizer plucks.

The Architecture of Traditional Serial MIDI

To understand why flamming occurs, one must look at how legacy MIDI hardware communicates. Traditional MIDI interfaces use a 5-pin DIN connector operating as an asynchronous serial communication protocol.

Unlike parallel connections, which can send multiple bits across several wires simultaneously, a serial connection sends data sequentially down a single wire, one bit at a time. The original MIDI 1.0 specification defines a fixed transmission rate of 31,250 bits per second (31.25 kbaud).

Because data can only move as a single-file stream of bits, true simultaneity is physically impossible over a standard MIDI cable. Every single musical event must wait in line for the preceding event to finish transmitting.

The Math Behind a Ten-Note Chord

The physical delay introduced by a ten-note chord can be measured directly using standard MIDI data structures and the cable's fixed baud rate.

1. Frame Size and Byte Duration

MIDI data is packaged into 10-bit asynchronous frames:

  • 1 start bit
  • 8 data bits (1 byte)
  • 1 stop bit

At a transmission speed of 31,250 bits per second, each individual bit takes 32 microseconds (\(0.032\text{ ms}\)) to travel down the line:

\[\frac{1 \text{ second}}{31,250 \text{ bits}} = 0.000032 \text{ seconds} = 0.032\text{ ms per bit}\]

Because each byte requires 10 bits, transmitting a single byte of MIDI data requires 0.32 milliseconds:

\[10 \text{ bits} \times 0.032\text{ ms} = 0.32\text{ ms per byte}\]

2. The Size of a Note-On Message

A standard MIDI Note-On message requires three distinct bytes:

  1. Status Byte: Specifies the command (Note-On) and the target MIDI channel.
  2. Data Byte 1: Specifies the Note Number (pitch from 0–127).
  3. Data Byte 2: Specifies the Velocity (force from 0–127).

Sending one fully defined Note-On command requires:

\[3 \text{ bytes} \times 0.32\text{ ms} = 0.96\text{ ms}\]

3. Calculating the Total Delay for Ten Notes

If an artist plays a ten-note chord where all notes are struck at the exact same instant, the transmitting device must queue ten separate Note-On messages.

  • Standard Transmission: Without optimization, ten 3-byte messages equal 30 bytes. \[30 \text{ bytes} \times 0.32\text{ ms} = 9.6\text{ ms}\] The tenth note leaves the cable nearly 10 milliseconds after the first note begins transmission.

  • Running Status Optimization: The MIDI standard includes an efficiency feature called "Running Status." If several consecutive messages share the same status byte (such as multiple Note-Ons on the same channel), the status byte only needs to be sent once. The remaining notes require only two data bytes each (pitch and velocity). For a ten-note chord:

    • 1 Status Byte + (10 notes \(\times\) 2 Data Bytes) = 21 bytes
    • \[21 \text{ bytes} \times 0.32\text{ ms} = 6.72\text{ ms}\]

Even under optimal conditions with Running Status enabled, the tenth note is delayed by 6.72 milliseconds relative to the first note.

Why This Causes Audible Flamming

Human auditory perception is sensitive to micro-timing differences in transient sounds. The threshold for detecting distinct timing differences between sharp audio events is generally between 2 and 5 milliseconds.

When a chord's notes are spread across 7 to 10 milliseconds:

  • The ear stops hearing the chord as a single, coherent acoustic impact.
  • The transients blur, making percussive sounds feel sloppy or sluggish.
  • If the chord is layered across multiple synthesizers daisy-chained via MIDI Thru ports, processing latency at each synth adds to the serial transmission delay, pushing the offset even further into the audible range.

While modern protocols like USB-MIDI, RTP-MIDI (Ethernet), and MIDI 2.0 feature substantially higher bandwidths that virtually eliminate this issue, hardware setups relying on original 5-pin DIN cables remain subject to the physical speed limits of 31.25 kbaud serial data.
