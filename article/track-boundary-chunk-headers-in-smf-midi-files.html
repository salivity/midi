Track Boundary Chunk Headers in SMF MIDI Files

Standard MIDI Files (SMF) rely on a chunk-based binary architecture to structure musical performances, metadata, and timing information. This article details the specific four-byte chunk identifier used to define track boundaries within an SMF file, explaining its binary representation, structural role, and how parsers interpret track data.

The Track Chunk Identifier: MTrk

The specific binary chunk header that identifies track boundaries inside a Standard MIDI File is MTrk. In hexadecimal notation, this four-byte ASCII sequence is represented as:

0x4D 0x54 0x72 0x6B

Whenever a MIDI parser encounters this sequence after the initial file header, it marks the beginning of an independent track chunk containing musical events, control data, or metadata.

Structure of the MTrk Chunk

Every track within an SMF file consists of three sequential components:

  1. Chunk Type (4 bytes): The literal ASCII string MTrk (4D 54 72 6B), serving as the track boundary marker.
  2. Chunk Length (4 bytes): A 32-bit, big-endian unsigned integer indicating the exact size in bytes of the track event data that directly follows. This value does not include the 8 bytes consumed by the MTrk identifier and the length field itself.
  3. Track Event Data (Variable length): A continuous stream of delta-times paired with MIDI channel events, System Exclusive (SysEx) events, or Meta-events.

Determining Track Boundaries

Track boundaries are governed by both the chunk length field and a mandatory terminating event:

  • Header-Defined Boundary: The 32-bit length field immediately following MTrk tells the parser precisely how many bytes belong to that track, allowing decoders to jump directly to the next track chunk without reading intermediate bytes.
  • Internal Termination Marker: By specification, the data payload inside an MTrk chunk must always conclude with the "End of Track" Meta-event. This event is represented by the binary sequence FF 2F 00.

While the header chunk (MThd) defines overall file parameters such as the format type and track count, the MTrk signature uniquely isolates and encapsulates each individual stream of performance data.
