How Arcade Button MIDI Controllers Work

A DIY arcade button MIDI controller converts mechanical impact into digital sound by capturing physical contact via responsive microswitches, processing the electrical state change through a microcontroller, and immediately dispatching MIDI "Note On" binary packets over USB to a host computer. This article explains the precise hardware and firmware pipeline that eliminates input lag, detailing electrical grounding, debouncing algorithms, MIDI message encoding, and USB-MIDI packet transmission.

1. Mechanical Closure and Electrical Grounding

Inside an arcade button sits a transient mechanical switch—typically a microswitch or a high-durability mechanical keyboard switch (such as Sanwa, Seimitsu, or Cherry MX). Under normal conditions, the circuit is open. The microcontroller’s input pin is held at a logic high voltage (typically 3.3V or 5V) using internal pull-up resistors.

When the arcade plunger is depressed, it forces internal metal contacts together, closing the circuit directly to ground (GND). This drops the electrical voltage on the microcontroller pin from logic high to logic low (0V) in fractions of a microsecond.

2. Microcontroller State Detection

The controller's brain—commonly a low-cost, high-performance microcontroller board like a Raspberry Pi Pico, Teensy, or Arduino with native USB support—continually monitors the digital input pins.

To achieve instantaneous response, firmware relies either on hardware interrupts or ultra-fast polling loops executing tens of thousands of times per second. When the firmware detects a transition from high to low (a falling edge), it recognizes that a strike has occurred.

3. Latency-Free Debouncing

Mechanical contacts inside switches physically bounce against each other for a few milliseconds upon collision, creating electrical noise that can register as rapid, false re-triggers.

Standard delay-based debouncing introduces noticeable latency. Instead, high-performance arcade MIDI controllers use a "fire-on-first-edge" algorithm:

  • The firmware immediately triggers the note event upon the initial contact closure (instantaneous trigger).
  • A lockout timer (typically 5 to 15 milliseconds) starts immediately afterward, ignoring any chatter from mechanical bounce.
  • Once the timer clears and the switch is released, the pin is armed for the next press.

This design ensures latency remains sub-millisecond, preserving the tactile responsiveness essential for finger drumming and live performance.

4. Constructing the MIDI Note On Packet

The moment the switch state is confirmed, the microcontroller generates a standard 3-byte MIDI Note On message:

  1. Status Byte: Identifies the command and MIDI channel (e.g., 0x90 indicates Note On on Channel 1).
  2. Data Byte 1: The pitch or note number assigned to that button (e.g., 0x3C for Middle C / C4).
  3. Data Byte 2: The velocity value (0–127). Because basic arcade buttons are binary on/off switches without velocity sensors, firmware typically sends a static velocity, usually maximum impact (0x7F or 127).

5. High-Speed USB Transmission

Vintage 5-pin DIN MIDI connections run at a limited rate of 31,250 baud. Modern DIY controllers bypass this limitation by using native USB-MIDI running at Full-Speed USB (12 Mbps).

The microcontroller wraps the 3-byte MIDI message into a 4-byte USB-MIDI Event Packet and sends it directly across a hardware USB endpoint. The host computer's operating system natively recognizes the device via class-compliant USB drivers, delivering the Note On event to digital audio workstations (DAWs) or software samplers with negligible delay.
