How OSC to MIDI Bridges Convert Float to 7-Bit

An Open Sound Control (OSC) to MIDI bridge converts high-resolution, continuous floating-point values into standard 7-bit MIDI messages through a pipeline of clamping, linear scaling, quantization, and message formatting. Because OSC natively uses 32-bit floating-point numbers—typically normalized between 0.0 and 1.0—and standard MIDI Control Change (CC) commands require integer values from 0 to 127, the bridge translates modern network-based control data into legacy-compatible hardware and software instructions without overwhelming system bandwidth.

1. Clamping and Range Validation

The incoming OSC packet carries an address pattern and a payload containing one or more 32-bit floats. While software controllers usually output values between 0.0 and 1.0, uncalibrated sensors or custom interfaces may send numbers outside this expected range. The bridge first applies a clamping function to prevent overflow errors:

  • If the incoming float is less than the defined minimum (typically 0.0), it is forced to the minimum.
  • If the incoming float exceeds the defined maximum (typically 1.0), it is forced to the maximum.

2. Linear Scaling

Once validated, the float must be mapped to MIDI's discrete domain. For standard normalized inputs, the bridge multiplies the floating-point value by 127:

\[\text{Scaled Value} = \text{Input Float} \times 127\]

If the OSC stream uses an arbitrary range (such as sensor data from -1.0 to 1.0 or frequencies from 20.0 to 20000.0), the bridge applies standard linear interpolation:

\[\text{Scaled Value} = \left( \frac{\text{Input} - \text{In}_{\min}}{\text{In}_{\max} - \text{In}_{\min}} \right) \times 127\]

3. Quantization and Rounding

MIDI 1.0 controller bytes do not support fractional components. The scaled result is a floating-point number (e.g., \(0.5 \times 127 = 63.5\)) that must be converted into an integer.

Translators achieve this by applying a rounding algorithm:

  • Round to Nearest: Adding 0.5 and truncating (flooring) the decimal, ensuring even distribution across all 128 intervals.
  • Truncation: Discarding the fractional part entirely (less common, as it creates an uneven mapping for the value 127).

The output is a single integer strictly bounded between 0 and 127 (\(0000000_2\) to \(01111111_2\)).

4. Thinning and Change Detection

OSC operates over high-speed networks (UDP/IP), frequently transmitting updates at hundreds or thousands of packets per second. Sending a MIDI message for every single micro-change would cause MIDI buffer congestion and latency.

To prevent this, the bridge caches the last transmitted 7-bit value for that specific controller channel. If a newly calculated integer matches the cached value, the message is discarded. A new MIDI transmission only triggers when the floating-point change is large enough to shift the resulting integer to a new 7-bit step.

5. Byte Assembly and Dispatch

Finally, the bridge encapsulates the 7-bit integer into a standard 3-byte MIDI Control Change packet:

  • Status Byte: Identifies the message as a Control Change command and specifies the target MIDI channel (e.g., 0xB0 for CC on Channel 1).
  • Data Byte 1: Specifies the controller number (0–127).
  • Data Byte 2: Carries the newly converted 7-bit integer value (0–127).

The assembled message is then written to the designated virtual MIDI port, hardware serial interface, or USB endpoint.
