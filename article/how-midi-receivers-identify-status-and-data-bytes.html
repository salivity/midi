How MIDI Receivers Identify Status and Data Bytes

The MIDI (Musical Instrument Digital Interface) specification relies on a stream of 8-bit bytes to transmit musical performance data, where the Most Significant Bit (MSB) acts as a binary flag that immediately tells a receiver whether an incoming byte represents an operational command or the parameter data accompanying that command. By evaluating the state of this single bit—Bit 7—a MIDI receiver can determine the function of any byte without needing prior context, ensuring reliable, low-latency communication between instruments and digital audio devices.

The Binary Structure of MIDI Bytes

Every standard MIDI message consists of one or more 8-bit bytes (octets). These bits are numbered from 0 to 7, where Bit 0 is the least significant bit (LSB) and Bit 7 is the most significant bit (MSB).

  • Status Bytes (MSB = 1): If Bit 7 is high (1), the receiver interprets the byte as a status byte. These values fall in the hexadecimal range 0x80 to 0xFF (decimal 128 to 255).
  • Data Bytes (MSB = 0): If Bit 7 is low (0), the receiver interprets the byte as a data byte. These values fall in the hexadecimal range 0x00 to 0x7F (decimal 0 to 127).

Status Bytes: Defining the Command

When a receiver encounters a byte with an MSB of 1, it signals the beginning of a new instruction or event. The remaining seven bits define:

  1. The message type (such as Note On, Note Off, Control Change, or Pitch Bend).
  2. The target MIDI channel (channels 1 through 16).

For example, the byte 10010000 (0x90 in hexadecimal) has a 1 in the MSB position. The upper nibble (1001) defines a "Note On" command, while the lower nibble (0000) specifies MIDI Channel 1.

Data Bytes: Providing the Parameters

Once a receiver registers a status byte, it anticipates one or two data bytes to complete the instruction, depending on the message type. Because the MSB of a data byte is always 0, only the lower 7 bits are used to represent values, limiting MIDI data values to a range of 0 to 127.

Using the previous "Note On" example, the status byte 0x90 is followed by two data bytes:

  1. Note Number: e.g., 00111100 (0x3C, decimal 60, corresponding to Middle C).
  2. Velocity: e.g., 01000000 (0x40, decimal 64, representing key velocity).

Both bytes begin with 0, signaling to the receiver that they represent values rather than new commands.

Receiver Parsing Logic

At the hardware and firmware level, a MIDI receiver evaluates incoming serial data using simple bitwise masking. By applying a bitwise AND operation with 0x80 (binary 10000000), the receiver checks the state of Bit 7:

  • (incoming_byte & 0x80) != 0 evaluates to True: Process as a Status Byte.
  • (incoming_byte & 0x80) == 0 evaluates to False: Process as a Data Byte.

Operational Advantages

Using the MSB as an identifier provides critical advantages for real-time music hardware:

  • Error Recovery: If a cable is unplugged mid-transmission or bytes are corrupted, the receiver does not stay desynchronized. As soon as it encounters the next byte starting with 1, it immediately re-aligns to the start of a valid command.
  • Running Status: When sending repetitive commands (such as a rapid series of Note On messages), the MIDI protocol allows the transmitter to send the status byte once, followed by multiple pairs of data bytes. The receiver knows it is still processing the same command because incoming bytes continue to have an MSB of 0.
  • Real-Time Interrupts: System Real-Time messages (such as MIDI Clock or Active Sensing) have status bytes that can be sent at any time, even in the middle of another message's data stream. The receiver sees the 1 in the MSB, immediately processes the single-byte command, and resumes collecting data bytes for the original message.
