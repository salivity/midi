How MTS Bulk Dump Transmits Microtonal Mappings

The MIDI Tuning Standard (MTS) provides a standardized protocol for digital instruments to bypass standard twelve-tone equal temperament by transmitting precise pitch alterations via System Exclusive (SysEx) messages. This article explains how MTS bulk dumps transmit twelve-byte microtonal tuning mappings to compatible synthesizers, breaking down the underlying SysEx architecture, the structure of single-byte scale offsets, and how receiving hardware parses this data into playable microtonal scales.

SysEx Architecture and MTS Protocol

MIDI transmits non-standard control data, including custom microtonal scales, using System Exclusive (SysEx) messages. MTS defines both real-time and non-real-time universal SysEx formats. When a master controller, software sequencer, or patch editor sends a microtonal tuning mapping, it wraps the data in an MTS command structure.

The transmission begins with the standard universal SysEx header, which includes:

  • F0: SysEx start byte
  • 7E (or 7F): Universal Non-Real-Time or Real-Time identifier
  • Device ID: Specifies the target synthesizer (or 7F for a broadcast to all connected devices)
  • 08: Sub-ID #1, designating the message as a MIDI Tuning Standard command
  • Sub-ID #2: Defines the specific MTS dump format

The Twelve-Byte Scale/Octave Dump Format

While a full 128-note MTS bulk dump transmits 384 bytes of tuning data (allocating three bytes per MIDI note across the entire keyboard), MTS specifies an optimized format known as the Scale/Octave Tuning 1-Byte Dump (sub-ID 08).

Instead of mapping all 128 notes individually, this format defines a microtonal scale across a repeating twelve-tone octave. The core payload consists of exactly twelve data bytes, where each byte corresponds sequentially to a degree of the chromatic scale from C through B:

  1. Byte 1: C offset
  2. Byte 2: C# offset
  3. Byte 3: D offset
  4. Byte 4: D# offset
  5. Byte 5: E offset
  6. Byte 6: F offset
  7. Byte 7: F# offset
  8. Byte 8: G offset
  9. Byte 9: G# offset
  10. Byte 10: A offset
  11. Byte 11: A# offset
  12. Byte 12: B offset

Pitch Offset Encoding

Because standard MIDI data bytes are constrained to a 7-bit range (00 to 7F hexadecimal, or 0 to 127 decimal), each byte encodes relative pitch deviation rather than an absolute frequency.

In the single-byte octave format:

  • The value 40h (64 decimal) represents zero detune (equal temperament).
  • Values from 00h to 3Fh (0 to 63 decimal) represent negative detuning down to -64 cents.
  • Values from 41h to 7Fh (65 to 127 decimal) represent positive detuning up to +63 cents.
  • The resolution is exactly 1 cent per step, offering a ±64 cent modification range for each pitch class.

Channel Masking and Checksum Verification

Preceding the twelve-byte tuning block, the message includes three channel mask bytes. These bytes indicate which of the 16 MIDI channels should apply the microtonal mapping, allowing multitimbral synthesizers to maintain microtonal scales on specific channels while keeping others in standard tuning.

Following the twelve-byte tuning payload, the transmitting device appends:

  • Checksum Byte: A 7-bit XOR checksum of the entire SysEx data stream (excluding headers and terminators) used to detect transmission errors.
  • F7: The End of Exclusive (EOX) byte.

Synthesizer Parsing and Implementation

When a compatible synthesizer receives the MTS dump, it validates the SysEx header and calculates the checksum. Once verified, the synthesizer stores the twelve microtonal offsets in its local memory buffer.

When a standard MIDI Note-On message is received, the synthesizer determines the note's pitch class using a modulo-12 calculation (MIDI Note Number mod 12). It matches the result to the corresponding byte among the twelve stored offsets, calculates the final frequency by adding the designated cent deviation to the base pitch, and instructs its internal oscillators to sound the custom microtonal frequency.
