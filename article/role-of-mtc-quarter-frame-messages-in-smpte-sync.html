Role of MTC Quarter Frame Messages in SMPTE Sync

MIDI Time Code (MTC) Quarter Frame messages provide a bandwidth-efficient method for transmitting continuous SMPTE timecode across standard asynchronous MIDI serial lines. Instead of broadcasting the complete time address at every frame, which would quickly saturate the 31.25 kbaud MIDI bandwidth, the protocol distributes the timecode across a sequence of eight small messages. This allows receiving devices to maintain continuous, frame-accurate synchronization while leaving the serial line open for musical performance data.

Bandwidth Conservation over Serial Lines

Standard longitudinal SMPTE timecode (LTC) is an analog biphase signal that conveys complete hour, minute, second, and frame data in an 80-bit frame at rates of 24 to 30 frames per second. Translating this directly into MIDI via System Exclusive "Full Frame" messages requires 10 bytes per frame, consuming excessive bandwidth and creating timing jitter for normal MIDI channel events.

The Quarter Frame message solves this problem. It is a compact, two-byte System Common message that represents time continuously during normal forward or reverse playback. Because it consumes only two bytes per transmission, it operates at a fraction of the serial throughput, using roughly 7.5% of the total MIDI bandwidth at 30 frames per second.

Structure of the Quarter Frame Message

A Quarter Frame message consists of two bytes: a Status Byte followed by a single Data Byte.

  1. Status Byte (0xF1): Identifies the message as an MTC Quarter Frame message to the receiver's UART.
  2. Data Byte (0nnndddd):
    • The most significant bit is always 0 to denote standard MIDI data.
    • The next three bits (nnn, values 0 through 7) represent the Message Type or field index.
    • The lowest four bits (dddd) represent the actual 4-bit Data Nibble of the timecode value.

The Eight-Message Sequence

To convey a complete SMPTE time address, eight individual Quarter Frame messages must be sent sequentially. The data payload of each message type is organized as follows:

  • Type 0: Frame Count (Low Nibble, bits 0–3)
  • Type 1: Frame Count (High Nibble, bit 4; bits 5–7 are 0)
  • Type 2: Seconds Count (Low Nibble, bits 0–3)
  • Type 3: Seconds Count (High Nibble, bits 4–6; bit 7 is 0)
  • Type 4: Minutes Count (Low Nibble, bits 0–3)
  • Type 5: Minutes Count (High Nibble, bits 4–6; bit 7 is 0)
  • Type 6: Hours Count (Low Nibble, bits 0–3)
  • Type 7: Hours Count (High Nibble, bit 4) plus the SMPTE Rate Code (bits 5–6)

The SMPTE rate flags embedded in Type 7 inform the receiver of the running standard: 24 fps, 25 fps, 29.97 fps drop-frame, or 30 fps non-drop.

Transmission Timing and Clock Extrapolation

Quarter Frame messages are transmitted at a frequency four times the current SMPTE frame rate. For example, at 30 fps, a message is transmitted every 8.33 milliseconds (120 Hz).

Because the complete time address is segmented into eight distinct messages, it requires exactly two SMPTE frames to transmit the entire timecode sequence. To maintain continuous, sample-accurate synchronization, the receiving device does not wait for a full eight-message cycle to update its location. Instead:

  1. Phase and Rate Tracking: Each arrival of an 0xF1 byte acts as a high-resolution sub-frame clock pulse (one quarter of a frame duration), driving an internal flywheel or phase-locked loop (PLL) in the receiver.
  2. Positional Decoding: The receiver reads the incoming data nibbles to assemble the full address. Since an eight-message cycle completes every two frames, the reconstructed time represents the timecode at the start of that two-frame window.
  3. Offset Compensation: Software and hardware decoders account for this two-frame transmission latency by internally advancing the running timecode counter by two frames once the Type 7 message is validated.

If the transport shuttles, locates, or jumps abruptly, the transmitter pauses Quarter Frame generation and sends a single 10-byte SysEx Full Frame message (0xF0 0x7F ... 0xF7) to relocate the slave device immediately before returning to regular Quarter Frame transmission.
