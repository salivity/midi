Maximum Note Frequency Over Serial MIDI 1.0

The theoretical maximum rate for transmitting complete musical notes (each consisting of a Note-On and a Note-Off event) over a standard serial MIDI 1.0 connection is 781.25 notes per second using Running Status, or 520.83 notes per second without it. If measuring raw Note-On events without pairing them to Note-Off releases, the absolute ceiling reaches 1,562.5 Note-On messages per second. This article breaks down the physical serial bandwidth, byte framing, and protocol optimizations that define these exact thresholds.

The Physical Baud Rate and Byte Capacity

Standard MIDI 1.0 operates over a current loop serial interface clocked at an exact rate of 31,250 baud (bits per second).

Serial MIDI uses asynchronous framing where every transmitted byte requires:

  • 1 Start bit
  • 8 Data bits
  • 1 Stop bit

This totals 10 bits per MIDI byte. Dividing the baud rate by the bits per byte gives the maximum throughput:

\[\frac{31,250 \text{ bits/second}}{10 \text{ bits/byte}} = 3,125 \text{ bytes/second}\]

A single serial MIDI 1.0 line can never transmit more than 3,125 bytes per second under any condition.

Standard Note Transmission (Without Running Status)

A standard MIDI Note-On message requires three bytes:

  1. Status byte (0x9n, indicating Note-On and channel)
  2. Data byte 1 (Note number, 0–127)
  3. Data byte 2 (Velocity, 1–127)

A standard Note-Off message also requires three bytes:

  1. Status byte (0x8n, indicating Note-Off and channel)
  2. Data byte 1 (Note number, 0–127)
  3. Data byte 2 (Release velocity, 0–127)

Alternatively, a Note-On command with a velocity of zero acts as a Note-Off, which also takes three bytes.

  • Raw Note-On Rate: \(\frac{3,125}{3} \approx 1,041.67 \text{ Note-On messages/second}\)
  • Complete Note Rate (Note-On + Note-Off): A full note requires 6 bytes (3 bytes to start, 3 bytes to stop). \[\frac{3,125}{6} \approx 520.83 \text{ complete notes/second}\]

Maximum Note Transmission (With Running Status)

MIDI 1.0 includes an optimization called Running Status. If consecutive messages share the same status byte (the same command on the same channel), the status byte does not need to be resent.

By pairing Note-On commands (velocity > 0) with zero-velocity Note-On commands (which function as Note-Off), the status byte 0x9n only needs to be sent once. Every subsequent note event then requires only 2 data bytes (Note number and Velocity).

Under continuous Running Status:

  • Raw Note-On Rate: \(\frac{3,125}{2} = 1,562.5 \text{ Note-On messages/second}\)
  • Complete Note Rate (Note-On + Zero-Velocity Note-Off): A complete cycle requires 4 data bytes (2 bytes to start the note, 2 bytes to end the note). \[\frac{3,125}{4} = 781.25 \text{ complete notes/second}\]

Summary of Theoretical Limits

  • 781.25 Hz is the absolute theoretical maximum frequency for complete musical notes (On and Off) using Running Status.
  • 520.83 Hz is the maximum frequency for complete musical notes using standard 3-byte messages.
  • 1,562.5 Hz is the theoretical limit if transmitting continuous Note-On triggers without corresponding Note-Off messages.
