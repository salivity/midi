Converting Potentiometer ADC Voltage to Smooth MIDI CC

This article explains how hardware and software work together to transform mechanical knob turns into clean musical control data. Analog potentiometers function as variable voltage dividers that output fluctuating electrical potentials to a microcontroller's Analog-to-Digital Converter (ADC). The ADC digitizes these voltages into high-resolution integer values, which software then filters to eliminate electrical noise and jitter. Finally, these stabilized readings are scaled and formatted into standard 7-bit MIDI Continuous Controller (CC) messages, producing seamless, zipper-free parameter changes in synthesizers and digital audio workstations.

The Voltage Divider: Creating the Analog Signal

An analog potentiometer features three terminals: one connected to the microcontroller's supply voltage (typically 3.3V or 5V), one connected to ground (0V), and a center wiper connected directly to an ADC pin. As the user rotates the knob, the internal resistive strip divides the voltage proportionally based on the wiper's physical position.

The wiper outputs a continuous, smooth analog voltage ranging from 0V to the supply rail. Because this signal is completely analog, its resolution is theoretically infinite, representing the exact physical angle of the potentiometer shaft at any given microsecond.

ADC Sampling and Quantization

Microcontrollers cannot process continuous analog voltages directly; they must sample and quantize the signal using an onboard ADC.

  1. Sampling: The ADC periodically reads the voltage level at a predefined sampling rate (typically hundreds or thousands of times per second).
  2. Quantization: The ADC converts the sampled voltage into a discrete digital number based on its bit resolution:
    • A 10-bit ADC divides the voltage range into 1,024 discrete steps (values from 0 to 1023).
    • A 12-bit ADC provides 4,096 discrete steps (values from 0 to 4095).

If a 5V supply is used with a 10-bit ADC, each digital step represents approximately 4.88 millivolts.

Eliminating Jitter with Software Smoothing

Raw ADC readings are inherently susceptible to electrical noise caused by thermal fluctuations, power supply ripple, and mechanical resistance variations within the potentiometer. Without processing, an untouched potentiometer will fluctuate randomly between adjacent ADC values. If mapped directly, this noise causes constant, unwanted MIDI message transmission (known as "MIDI CC spam" or "chatter").

Developers apply several algorithmic techniques to create smooth, reliable data:

Exponential Moving Average (EMA)

An EMA acts as a digital low-pass filter, attenuating high-frequency noise while preserving intentional knob movements:

\[\text{FilteredValue} = (\alpha \times \text{CurrentADC}) + ((1 - \alpha) \times \text{PreviousFilteredValue})\]

A smaller weight factor (\(\alpha\)) produces smoother output but introduces slight latency, while a larger value makes the control feel more responsive at the expense of stability.

Hysteresis and Deadbands

To prevent oscillation between two numbers when the potentiometer sits on a boundary, a hysteresis algorithm is implemented. The software requires the raw value to change by more than a specified threshold (a deadband, often 2 to 4 ADC steps) before registering a new position. Once the threshold is crossed, the software updates the stored value.

Mapping and Transmitting MIDI CC Data

Standard MIDI Continuous Controller messages use a 7-bit data byte, which yields 128 discrete values from 0 to 127.

To convert the smoothed, high-resolution ADC value into the 7-bit MIDI domain, the value is scaled:

  • For a 10-bit reading (0–1023), the value can be bit-shifted right by 3 bits (ADC_val >> 3) or divided by 8.
  • Linear mapping functions scale the filtered range to ensure that absolute 0V reaches a MIDI CC of 0, and the maximum rail voltage reaches 127.

Finally, the microcontroller compares the new 7-bit value to the previously sent MIDI CC value. A standard 3-byte MIDI message—consisting of the Status Byte (Control Change + Channel), the Controller Number (e.g., CC 74 for filter cutoff), and the Data Value (0–127)—is transmitted across the serial interface or via USB-MIDI only when a change occurs. This event-driven transmission prevents bus congestion while delivering responsive, jitter-free control.
