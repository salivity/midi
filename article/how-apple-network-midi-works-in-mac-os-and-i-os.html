How Apple Network MIDI Works in macOS and iOS

Apple's native Network MIDI driver enables seamless, low-latency transmission of Musical Instrument Digital Interface (MIDI) data over local Wi-Fi and Ethernet networks. Operating directly within the CoreMIDI framework on both macOS and iOS, this built-in capability eliminates the need for third-party drivers or proprietary hardware interfaces. This article explains the underlying protocol, the role of zero-configuration networking, the CoreMIDI system architecture, and how the driver manages synchronization and packet reliability.

The Underlying Protocol: RTP-MIDI

Apple’s Network MIDI implementation is built entirely on the standard RTP-MIDI payload format, specified by the Internet Engineering Task Force (IETF) in RFC 4695 and updated in RFC 6295.

Instead of relying on standard TCP—which prioritizes lossless delivery at the expense of latency through packet retransmission—the driver uses the Real-time Transport Protocol (RTP) running over User Datagram Protocol (UDP). Because UDP is connectionless and does not require packet handshakes for every payload, it drastically reduces transmission overhead and minimizes jitter, both of which are critical for live musical performance and precise sequencing.

Device Discovery via Bonjour

To simplify device connections without manual IP configuration, the Apple Network MIDI driver utilizes Bonjour (Apple's implementation of zero-configuration networking).

When a network MIDI session is created, the system uses multicast DNS (mDNS) and DNS Service Discovery (DNS-SD) to advertise the session across the local subnet under the _apple-midi._udp service type. Devices running macOS or iOS constantly listen for these service advertisements. Once discovered, devices can initiate connections through a simple invite-and-accept handshake, automatically negotiating UDP port assignments—typically utilizing an even/odd port pair for control messages and data transmission.

Integration within CoreMIDI

At the operating system level, Network MIDI is an integrated component of CoreMIDI:

  • macOS: Users configure network sessions through the native Audio MIDI Setup utility (specifically, the MIDI Studio's Network Session panel). The OS creates virtual MIDI source and destination endpoints that appear to Digital Audio Workstations (DAWs) and software instruments just like physical USB or DIN MIDI hardware.
  • iOS: Network MIDI functionality is directly accessible to developers via the MIDINetworkSession class within the CoreMIDI framework. iOS apps can programmatically enable network sessions, advertise endpoints, and connect to remote hosts. When active, network endpoints appear within any CoreMIDI-compatible iOS synthesizer or sequencer.

Clock Synchronization and Latency Management

Musical timing requires consistent synchronization across independent system clocks. The Network MIDI driver uses periodic exchange of synchronization packets to measure the Round-Trip Time (RTT) between endpoints.

By analyzing RTT and transmission delays, the driver establishes a shared temporal reference between the sender and receiver. MIDI events are transmitted with embedded timestamps. This allows the receiving operating system to buffer incoming events slightly and schedule playback at the precise intended moment, effectively neutralizing network jitter without introducing perceivable latency.

Fault Tolerance and the Recovery Journal

Because UDP does not guarantee packet delivery, standard network drops could lead to undesirable musical errors, such as stuck "hanging" notes or missed pitch-bend releases.

To solve this, Apple's RTP-MIDI driver implements a "Recovery Journal." Each transmitted packet contains not only the newest MIDI event but also a compact summary of recent historical controller states, note activations, and channel configurations. If an intermediate packet is lost in transit over Wi-Fi, the receiving device inspects the recovery journal in the subsequent packet to reconstruct the missing state immediately, ensuring notes are silenced and parameters stay in sync.
