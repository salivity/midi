MIDI 1.0 Byte Framing: Start and Stop Bits Guide

The MIDI 1.0 specification relies on standard asynchronous serial communication to transfer musical performance and control data between hardware devices without a shared system clock. To maintain synchronization across simple serial lines, MIDI packages every eight-bit byte into a rigid ten-bit frame consisting of one start bit, eight data bits, and one stop bit. This article explains how start and stop bits function within the MIDI 1.0 protocol, detailing the electrical transitions, clock synchronization, and data alignment required for reliable transmission.

Asynchronous Serial Architecture

Asynchronous serial communication transfers data sequentially along a single signal path without transmitting an accompanying clock signal. Because the receiver and transmitter maintain their own independent internal clocks, they must agree on a predetermined transmission speed and frame format. MIDI 1.0 specifies a fixed transmission rate of 31.25 kbaud (31,250 bits per second), with a tolerance of ±1%.

At this speed, the duration of each individual bit is exactly 32 microseconds. To correctly parse data at the receiving end, the MIDI interface wraps every byte in framing bits that indicate precisely where a byte begins and ends.

The Idle Line and Start Bit

When no data is being sent over a MIDI cable, the communication line remains in an "idle" or "Mark" state. Electrically, this is represented by a logical 1 (current loop closed/active or voltage high, depending on the internal stage of the hardware UART).

When a device transmits a byte, it first generates a start bit:

  • Polarity: The start bit transitions the line from logical 1 (Mark) to logical 0 (Space).
  • Function: This falling edge signals the receiver's Universal Asynchronous Receiver-Transmitter (UART) that a byte transmission has begun.
  • Synchronization: Upon detecting the transition to logical 0, the receiver resets its internal clock counter. It waits 1.5 bit periods (48 microseconds) to sample the line at the exact center of the first actual data bit, minimizing the risk of misreading voltage transitions caused by signal rise and fall times.

Data Bits Transmission

Following the start bit, the transmitter sends the eight data bits that make up the actual MIDI message component:

  • Order: Bits are transmitted Least Significant Bit (LSB) first and Most Significant Bit (MSB) last (bit 0 through bit 7).
  • Role of MSB: In MIDI 1.0, the MSB distinguishes between Status bytes (MSB set to 1) and Data bytes (MSB set to 0).
  • Duration: The eight data bits consume a total of 256 microseconds (8 bits × 32 microseconds).

The Stop Bit

Immediately after the eighth data bit (bit 7) is transmitted, the sender outputs a stop bit:

  • Polarity: The stop bit transitions the line back to a logical 1 (Mark).
  • Duration: The MIDI specification requires a minimum of one stop bit duration (32 microseconds).
  • Function: The stop bit acts as a recovery interval. It guarantees that the line returns to the high idle state before any subsequent byte is sent. Without this transition back to logical 1, a receiver would be unable to recognize the falling edge of the next byte's start bit if the preceding byte ended with a logical 0.

Framing Errors and Timing Integrity

A ten-bit MIDI frame requires exactly 320 microseconds to complete:

\[\text{Total Frame Time} = (1 \text{ Start Bit} + 8 \text{ Data Bits} + 1 \text{ Stop Bit}) \times 32\,\mu\text{s} = 320\,\mu\text{s}\]

This yields a maximum continuous transmission capacity of 3,125 bytes per second.

If the receiver samples the line during the expected stop bit window and detects a logical 0 instead of a logical 1, a framing error occurs. Framing errors typically indicate clock drift between the transmitter and receiver, noise on the physical line, or interrupted transmissions. When a framing error occurs, the receiver generally discards the malformed byte, waiting until the line returns to the idle state before attempting to synchronize on the next valid start bit.
