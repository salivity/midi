Understanding MIDI Key Signature Meta Events

The MIDI Key Signature Meta Event communicates musical tonality within a standard MIDI file using a compact two-byte payload. Rather than storing explicit note names like "C" or "F#", the specification encodes the key by defining the count of accidentals alongside a binary mode flag. By combining the number of sharps or flats with the specified major or minor mode, MIDI playback engines and digital audio workstations can unambiguously deduce both the tonic root note and the tonal quality of the composition.

The Meta Event Structure

In standard MIDI file syntax, the Key Signature event is represented by the following byte sequence:

FF 59 02 sf mi

  • FF: The status byte indicating a Meta Event.
  • 59: The specific Meta Event type for a Key Signature.
  • 02: The length of the remaining data in bytes.
  • sf: The number of sharps or flats.
  • mi: The tonality mode (major or minor).

Encoding the Accidentals (sf)

The first data byte (sf) represents the position of the key along the Circle of Fifths as a signed 8-bit integer:

  • Positive values (0x01 to 0x07): Represent keys with one to seven sharps (e.g., 01 = 1 sharp, 02 = 2 sharps).
  • Zero (0x00): Represents zero accidentals (the natural key signature).
  • Negative values (0xFF to 0xF9 in two's complement): Represent keys with one to seven flats (e.g., -1 or 0xFF = 1 flat; -7 or 0xF9 = 7 flats).

Encoding the Tonality Mode (mi)

The second data byte (mi) dictates whether the key signature is interpreted as major or minor:

  • 00: Major key.
  • 01: Minor key.

The specification only defines 00 and 01. Alternate modes (such as Dorian, Mixolydian, or Phrygian) are not natively encoded and must be treated as their relative major or minor equivalents.

How the Tonic Root is Derived

The tonic root note is not explicitly stored; it is derived through the relationship between the accidental count (sf) and the mode (mi).

Because every key signature on the Circle of Fifths corresponds to one major key and its relative minor (which shares the exact same accidentals), the mi byte acts as a switch between the two possibilities:

  • When mi is 0x00 (Major): The sf value identifies the root directly from the major Circle of Fifths.
    • sf = 00, mi = 00: 0 accidentals, Major = C Major
    • sf = 01, mi = 00: 1 sharp, Major = G Major
    • sf = FE (-2), mi = 00: 2 flats, Major = B♭ Major
  • When mi is 0x01 (Minor): The root shifts three semitones (a minor third) down from the major key that shares the same accidental count.
    • sf = 00, mi = 01: 0 accidentals, Minor = A Minor (relative to C Major)
    • sf = 01, mi = 01: 1 sharp, Minor = E Minor (relative to G Major)
    • sf = FE (-2), mi = 01: 2 flats, Minor = G Minor (relative to B♭ Major)

Through this pair of values, the MIDI specification provides a standardized, mathematically concise method for software to map out both the correct pitch center and the harmonic context for notation and playback.
