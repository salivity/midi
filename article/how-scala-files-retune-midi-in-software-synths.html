How Scala Files Retune MIDI in Software Synths

This article explains how the Scala file format interfaces with software synthesizers to translate conventional 12-tone equal temperament (12-TET) MIDI input into arbitrary microtonal tunings. By reading pitch ratios and frequency reference maps, synthesis engines bypass the standard 12-note chromatic grid, dynamically assigning custom oscillator frequencies to standard MIDI note numbers.

The MIDI Frequency Limitation

Standard MIDI protocol defines note numbers as integers from 0 to 127. Under 12-TET, software synthesizers calculate an oscillator’s frequency using a fixed mathematical formula based on semitone offsets, typically anchored to MIDI Note 69 (A4) at 440 Hz:

\[f = 440 \times 2^{(n - 69) / 12}\]

Because MIDI note data lacks native microtonal pitch information beyond global or polyphonic pitch-bend messages, instruments require an external reference to redefine what pitch an incoming note number triggers. This reference is provided by Scala files.

The Structure of a Scala (.scl) File

A Scala file (.scl) is a plain-text document defining the relative intervals of a scale. It consists of three primary components:

  1. Description line: Human-readable text naming or describing the tuning.
  2. Note count: The number of intervals present in one scale cycle (often an octave, though not strictly required).
  3. Pitch definitions: A sequential list of intervals, written either as cents (values containing a decimal point, such as 1200.0 or 150.5) or as mathematical ratios (fractions such as 3/2 or 5/4).

The .scl file defines only intervals relative to a root pitch (1/1 or 0.0 cents); it does not dictate base frequencies or specific MIDI key assignments on its own.

Keyboard Mapping with .kbm Files

To link the relative intervals in an .scl file to physical MIDI keys, synthesizers utilize an optional accompanying keyboard mapping file (.kbm). The .kbm file specifies:

  • The scale size.
  • The lowest and highest MIDI key numbers to be retuned.
  • The formal key mapping (assigning specific scale degrees to specific MIDI notes).
  • The reference MIDI key (the note that anchors the scale, commonly Note 69).
  • The reference frequency (the absolute frequency in Hertz for that anchor note, such as 440.0 Hz).

If no .kbm file is loaded alongside the .scl file, the synth typically assumes a default mapping: scale degree 0 is assigned to MIDI Note 60 (Middle C) or Note 69 (A440), and degrees repeat cyclically across the keyboard every octave.

The Internal Engine Retuning Process

When a software synthesizer loads a Scala file, it executes the following steps:

  1. Parsing: The synth reads the text lines in the .scl and .kbm files, converting cents and ratios into internal floating-point values representing relative pitch multipliers.
  2. Lookup Table Generation: The engine builds an internal frequency lookup table (LUT) spanning all 128 MIDI notes. For each MIDI key number \(N\), it calculates the exact absolute frequency (\(f\)) in Hertz by applying the scale degree's ratio or cent value to the anchor frequency defined by the mapping.
  3. Phase Accumulator Adjustment: When a MIDI Note On event arrives, the synth does not calculate pitch using the standard logarithmic semitone formula. Instead, it reads the target frequency directly from the lookup table. The digital audio oscillator then adjusts its phase accumulator—the incremental value added to the waveform index per audio sample—to produce the exact target frequency directly.

Interfacing Protocols: Direct Engine vs. MTS

Modern software synthesizers implement this retuning through one of two primary architectural methods:

  • Native Retuning: Soft synths with built-in microtonal support (such as Surge XT, Vital, or Pianoteq) read the .scl directly. The audio generation core evaluates the custom pitch tables per voice, guaranteeing full polyphonic microtonal playback without consuming MIDI channels for pitch-bend offsets.
  • MIDI Tuning Standard (MTS): In modular or multi-plugin environments, tuning software transmits Scala data using MTS SysEx messages. The receiving synth parses these standard microtonal bulk dump messages, overwriting its internal pitch table to match the microtonal scale.
