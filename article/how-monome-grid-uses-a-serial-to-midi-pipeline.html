How Monome Grid Uses a Serial-to-MIDI Pipeline

The Monome grid is a minimalist tactile controller that intentionally omits native, hardcoded MIDI mappings. Instead, it relies on a flexible serial-to-MIDI virtual pipeline to translate physical button presses into complex musical output. By sending raw, low-latency serial data over USB to a host computer, the hardware interfaces with an intermediary translation service and a custom software logic engine, which converts interactive states into virtual MIDI messages routable to any digital audio workstation (DAW) or synthesizer.

1. Raw Serial Communication and Hardware Layer

The physical Monome grid contains no internal sound engine, pre-programmed scale modes, or fixed MIDI note assignments. Each key is an unassigned momentary switch backed by an independent, variable-brightness LED.

When a performer presses or releases a button, the grid’s internal microcontroller sends a lightweight serial packet over a standard USB connection. This message contains only the fundamental physical coordinates \((x, y)\) of the button and a binary state value (1 for press, 0 for release).

2. The Daemon: serialosc

Because modern audio applications typically look for standard MIDI or Open Sound Control (OSC) inputs rather than raw serial streams, an intermediary daemon called serialosc runs in the background on the host operating system.

  • Device Discovery: serialosc automatically detects Monome devices plugged in via USB through system-level serial drivers (such as FTDI).
  • Protocol Translation: It translates the low-level serial byte stream into high-level OSC packets.
  • Port Management: It assigns specific network ports (UDP) to the connected grid, enabling bidirectional communication between the hardware and software environments without requiring exclusive hardware access locks.

3. The Custom Logic Engine

The core musical intelligence lives within an execution environment configured to receive OSC messages from serialosc. Common environments include Max/MSP, Pure Data, SuperCollider, Monome’s standalone Norns ecosystem, or custom Python scripts.

Inside this environment, the custom performance logic is applied:

  • State Management: The software determines what a coordinate press represents based on the current page, layout, or playhead position (e.g., triggering a drum voice, modulating an LFO, or enabling a step in a polyphonic sequencer).
  • LED Feedback: The pipeline is bidirectional. The logic engine sends OSC messages back through serialosc to illuminate or dim specific coordinates on the grid, providing visual feedback of clocks, playheads, and active toggles.

4. The Virtual MIDI Bridge

Once the custom logic engine processes an event, it synthesizes the data into standard MIDI specifications (such as Note-On, Note-Off, CC values, Pitch Bend, and Clock). Because these messages are generated entirely in software, they must travel through a virtual MIDI pipeline to reach audio software.

  • macOS: Employs the native Inter-Application Communication (IAC) Driver.
  • Windows: Uses third-party virtual loopback drivers such as loopMIDI.
  • Linux: Uses ALSA virtual MIDI kernel modules (snd-virmidi).

The logic engine routes the generated MIDI messages to one of these virtual output ports.

5. Final Ingestion by the Audio Target

External software—such as Ableton Live, Bitwig Studio, or standalone virtual instruments—sees the virtual loopback driver as a standard physical MIDI input device.

The complete event cycle occurs in milliseconds: a button press on the grid generates a serial message, serialosc converts it to OSC, the custom script computes the compositional logic, the script emits MIDI into the virtual pipeline, and the DAW registers the performance event as musical control data.
