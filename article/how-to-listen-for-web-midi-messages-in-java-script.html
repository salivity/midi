How to Listen for Web MIDI Messages in JavaScript

The Web MIDI API enables web applications to interact directly with connected musical instruments, controllers, and synthesizers. This article provides a straightforward guide on how to request MIDI permissions, detect connected input devices, attach the midimessage event listener, and parse incoming MIDI data such as note presses, velocity, and control changes.

Requesting Web MIDI Access

Before listening to MIDI hardware, your application must request access from the user's browser using navigator.requestMIDIAccess(). Note that this API requires a secure context (HTTPS or localhost).

async function initMIDI() {
  if (!navigator.requestMIDIAccess) {
    console.error("Web MIDI API is not supported in this browser.");
    return;
  }

  try {
    const midiAccess = await navigator.requestMIDIAccess();
    console.log("MIDI access granted.");
    setupInputs(midiAccess);
  } catch (error) {
    console.error(`Failed to get MIDI access: ${error.message}`);
  }
}

Accessing Inputs and Listening for midimessage

Once access is granted, the MIDIAccess object contains an inputs map representing all connected MIDI input devices. You can loop through these inputs and assign an event listener to the midimessage event for each one.

You can handle the event using either the onmidimessage property or addEventListener:

function setupInputs(midiAccess) {
  const inputs = midiAccess.inputs.values();

  for (const input of inputs) {
    console.log(`Connected to device: ${input.name}`);
    
    // Attach listener using addEventListener
    input.addEventListener("midimessage", handleMIDIMessage);
  }

  // Handle devices plugged in or unplugged while the app is running
  midiAccess.onstatechange = (event) => {
    if (event.port.type === "input" && event.port.state === "connected") {
      event.port.addEventListener("midimessage", handleMIDIMessage);
    }
  };
}

Parsing the MIDI Message

The midimessage event provides a data property, which is a Uint8Array containing the raw MIDI bytes (typically three bytes for standard channel voice messages):

  1. Status Byte (data[0]): Defines the message type (e.g., Note On, Note Off, Control Change) and the MIDI channel.
  2. Data Byte 1 (data[1]): Specifies the note number (0–127) or controller number.
  3. Data Byte 2 (data[2]): Specifies the velocity (0–127) or value.
function handleMIDIMessage(event) {
  const [status, note, velocity] = event.data;
  const command = status >> 4;
  const channel = status & 0xf;

  switch (command) {
    case 0x9: // Note On
      if (velocity > 0) {
        console.log(`Note On: ${note} | Velocity: ${velocity} | Channel: ${channel}`);
      } else {
        // A velocity of 0 is often interpreted as Note Off
        console.log(`Note Off: ${note} | Channel: ${channel}`);
      }
      break;

    case 0x8: // Note Off
      console.log(`Note Off: ${note} | Velocity: ${velocity} | Channel: ${channel}`);
      break;

    case 0xb: // Control Change (knobs, sliders, pedals)
      console.log(`Control Change: Controller ${note} | Value: ${velocity}`);
      break;

    default:
      console.log(`Other MIDI Command: ${command.toString(16)}`, event.data);
  }
}

Calling initMIDI() starts the listener, allowing your application to receive and respond to real-time physical MIDI hardware input directly within the browser.
