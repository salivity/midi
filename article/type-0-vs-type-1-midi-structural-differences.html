Type 0 vs Type 1 MIDI: Structural Differences

Standard MIDI Files (SMF) rely on a standardized binary format to store musical performance data, primarily categorized into Type 0 and Type 1 formats. While both formats utilize the same underlying MIDI message specifications and sound identical during playback, their primary structural difference lies in how tracks are organized within the file: Type 0 merges all channel data and meta-events into a single track chunk, whereas Type 1 separates the data across multiple, synchronized track chunks.

Header Chunk Differences (MThd)

Every Standard MIDI File begins with an MThd chunk, which defines the file's basic operational parameters across 14 bytes: the chunk ID (MThd), chunk length (always 6 bytes), format type, number of tracks (ntrks), and division (time resolution).

  • Type 0: The format field is explicitly set to 0x0000, and the track count field (ntrks) is always fixed to 0x0001.
  • Type 1: The format field is set to 0x0001, and the track count field can specify two or more tracks (ntrks \(\ge 2\)).

Track Chunk Organization (MTrk)

The actual musical performance, tempo maps, and control events are stored in one or more MTrk chunks.

Type 0: Consolidated Single Track

A Type 0 file contains exactly one MTrk chunk. All musical events across up to 16 MIDI channels are multiplexed into a single chronological stream.

  • Event Interleaving: Notes, pitch bends, and control changes for every instrument are interleaved chronologically based on their delta-times.
  • Global Meta-Events: Meta-events such as tempo changes, time signatures, key signatures, and text markers are embedded directly within this single sequence alongside note data.
  • Processing: Hardware or software reading a Type 0 file does not need to synchronize multiple independent streams; it simply reads through a single stream of delta-time events from start to finish.

Type 1: Multi-Track Synchronization

A Type 1 file contains multiple independent MTrk chunks designed to play simultaneously.

  • Track Separation: Individual instruments, parts, or MIDI channels are isolated into their own dedicated track chunks (for example, Track 1 for drums, Track 2 for bass, Track 3 for piano).
  • Tempo Map Track: By convention, the first track (Track 0) acts as the tempo map. It contains global metadata, including tempo, time signature, key signature, and SMPTE offset events, but typically contains no note-on or note-off events.
  • Synchronization: Each track maintains its own independent sequence of delta-times relative to the start of the sequence. The playback engine is responsible for maintaining a playback pointer for each track, reading them simultaneously, and dynamically merging the streams according to the global clock defined in the header.

Functional Implications of the Architecture

The structural distinction between the two types dictates their common use cases:

  • Type 0 minimizes memory overhead and eliminates the need for dynamic stream-merging logic, making it historically popular for hardware synthesizers, tone generators, and simple playback engines.
  • Type 1 mirrors the multitrack architecture of modern Digital Audio Workstations (DAWs) and sequencers, allowing users to mute, solo, edit, and quantize individual instrument tracks independently without affecting other channels.
