Universal MIDI Packet Header: Packet Size and Type

The Universal MIDI Packet (UMP) format is the foundational data container designed for modern MIDI communication, unifying both MIDI 1.0 and MIDI 2.0 protocols across high-speed digital transports like USB and Ethernet. At the core of every UMP is its header, located in the first four bits of the initial 32-bit word, which acts as the message's primary identifier. This header explicitly dictates the functional classification of the payload and establishes the exact byte length of the entire packet, enabling receiving devices to parse and process continuous MIDI data streams without framing ambiguity.

The Universal MIDI Packet Architecture

A Universal MIDI Packet consists of one to four 32-bit words (32, 64, 96, or 128 bits). Unlike legacy MIDI 1.0 byte streams that relied on variable-length status and data bytes with start/stop framing, every UMP message is strictly bounded and self-contained.

The structure of the first 32-bit word is standardized across all UMP messages:

  • Bits 31–28 (Nibble 0): Message Type (MT)
  • Bits 27–24 (Nibble 1): Group Field
  • Bits 23–16 (Byte 1): Status Byte / Opcode
  • Bits 15–0 (Bytes 2 and 3): Message-specific data or additional routing

Defining Message Type via the MT Field

The Message Type (MT) is a 4-bit identifier spanning bits 31 through 28 of the first word. Because it is four bits wide, it supports 16 distinct categories (hexadecimal values 0x0 through 0xF).

The MT value informs the parser of the exact semantic meaning of the payload:

  • 0x0 (Utility Messages): Carries non-musical synchronization, jitter reduction timestamps, and no-op messages.
  • 0x1 (System Real-Time & System Common): Transports standard real-time messages (Clock, Start, Stop) and common messages (Tune Request, Song Select).
  • 0x2 (MIDI 1.0 Channel Voice Messages): Carries legacy 7-bit MIDI 1.0 channel messages (Note On, Note Off, Control Change) in an encapsulated format.
  • 0x3 (Data 64-bit): Used for 7-bit System Exclusive (SysEx) data chunks.
  • 0x4 (MIDI 2.0 Channel Voice Messages): Carries expanded MIDI 2.0 messages featuring high-resolution 16-bit controls, 32-bit velocity, per-note pitch bend, and attribute data.
  • 0x5 (Data 128-bit): Used for 8-bit System Exclusive messages and Mixed Data Set transfers.
  • 0xD (Flex Data): Transports metadata, lyrics, text, and chord information.
  • 0xF (Stream Messages): Used for protocol discovery, endpoint configuration, and function block management.
  • Note: Values 0x6 through 0xC and 0xE are reserved for future protocol expansions.

How the Header Determines Packet Size

In the UMP specification, packet length is not defined by an arbitrary byte counter. Instead, the Message Type directly locks the packet to a fixed size. A parser inspects bits 31–28 of an incoming 32-bit word and immediately knows how many additional 32-bit words follow before the next packet begins:

Message Type (MT) Name / Category Word Count Total Bit Length Total Byte Length
0x0 Utility Messages 1 Word 32 bits 4 bytes
0x1 System Real-Time / Common 1 Word 32 bits 4 bytes
0x2 MIDI 1.0 Channel Voice 1 Word 32 bits 4 bytes
0x3 Data Messages (SysEx 7-bit) 2 Words 64 bits 8 bytes
0x4 MIDI 2.0 Channel Voice 2 Words 64 bits 8 bytes
0x5 Data Messages (SysEx 8-bit) 4 Words 128 bits 16 bytes
0xD Flex Data 4 Words 128 bits 16 bytes
0xF UMP Stream Messages 4 Words 128 bits 16 bytes

If a parser reads a word starting with an MT of 0x2, it processes only that single 32-bit word. If the parser reads an MT of 0x4, it reads the current 32-bit word along with the subsequent 32-bit word to complete the 64-bit structure before resetting to read the next header.

Group Field Integration

Directly adjacent to the Message Type is the 4-bit Group field (bits 27–24). While the MT specifies packet size and structural classification, the Group field designates one of 16 virtual cable destinations within the same physical connection. Together, the MT and Group nibbles allow modern MIDI hardware to multiplex up to 16 completely independent MIDI streams (each capable of 16 channels) inside deterministic, fixed-boundary packets.
