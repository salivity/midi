Save Organ Registrations Using MIDI SysEx

Modern digital and hybrid pipe organs allow performers to save and recall complex stop registrations beyond internal memory limits by transmitting MIDI System Exclusive (SysEx) dumps to external devices. This article explains the technical mechanics of organ SysEx data, the necessary hardware and software tools required, and the step-by-step procedure for capturing, storing, and transmitting SysEx data packets back to the console to instantly restore entire registration combinations.

Understanding Organ SysEx Communication

Unlike standard MIDI messages that handle note-on/off events and continuous controllers, System Exclusive (SysEx) messages are manufacturer-specific data packets designed to transmit proprietary information. In digital consoles (such as those from Allen, Rodgers, Johannus, or Viscount) and pipe organs equipped with modern solid-state combination actions, SysEx messages encode the state of every stop tab, drawknob, coupler, and combination piston.

A single SysEx registration dump includes the manufacturer ID, the specific model identifier, command instructions, the raw bitmapped data detailing which stops are engaged or disengaged across all divisions, and an End of Exclusive (EOX) byte (F7).

Required Hardware and Software

To manage SysEx dumps, an organist needs:

  1. A MIDI Interface: A reliable, low-latency USB-to-MIDI interface connected to the organ console's standard 5-pin DIN MIDI IN and MIDI OUT ports, or a direct USB-MIDI connection if the console supports it.
  2. A SysEx Librarian or DAW: Free software utilities are the standard tool for this task:
    • Windows: MIDI-OX or Bome SendSX.
    • macOS: Snoize SysEx Librarian.
    • iOS/iPadOS: Apps such as Sysex Base (via a compatible camera connection kit/MIDI interface).

How to Save a Registration (Sending the Dump to a Computer)

  1. Establish Connections: Connect the organ's MIDI OUT port to the computer interface's MIDI IN port.
  2. Set the Software to Record: Open your SysEx utility software, select your MIDI interface as the active input, and enable the "Record Many SysEx" or "Receive Dump" mode. The software is now waiting for an incoming stream.
  3. Trigger the Console Dump:
    • Navigate to the organ console's onboard menu system (often found under MIDI Settings, Memory, or Sequencer).
    • Select the option labeled SysEx Dump, Send Memory, or MIDI Save. Many consoles allow you to choose whether to send the entire piston memory, specific memory levels, or only the currently active registration.
    • Confirm the operation. The console's display will typically read "Transmitting..." as the data is pushed.
  4. Save and Archive: The software will display the received byte count and payload. Save this captured capture as a raw .syx file. Use a precise naming convention containing the composer, piece, console model, and date (e.g., Bach_Passacaglia_MemLevel3.syx).

How to Recall a Registration (Sending the Dump to the Organ)

  1. Establish Connections: Connect the computer interface's MIDI OUT port to the organ's MIDI IN port.
  2. Prepare the Console: Turn on the console and disengage any memory lock switches or write-protect settings. Many organs automatically listen for valid SysEx headers on their primary MIDI channel without needing to enter a dedicated receive menu.
  3. Transmit the File: In the SysEx software, load your saved .syx file and click "Send" or "Transmit."
  4. Observe the Console: If the console features motorized drawknobs or lighted stop tabs, the physical stops will move or illuminate to match the saved state. If the dump contains a multi-level combination memory backup, the onboard internal memory levels will populate automatically.

Critical Considerations and Troubleshooting

  • Buffer Overruns and Speed Throttling: Physical solenoids on drawknob consoles require electrical current and time to engage. If stops fail to actuate or drops occur, lower the transmission speed inside the SysEx software by increasing the delay between data packets (set packet buffers to 256 or 512 bytes, with a 50–100 millisecond delay between buffers).
  • Firmware Matching: SysEx dumps are strictly tied to specific console firmware architectures. A dump taken from an organ running one firmware revision may not successfully parse if the console's internal software is later upgraded. Keep firmware logs alongside archived .syx files.
