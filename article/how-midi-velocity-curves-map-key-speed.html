How MIDI Velocity Curves Map Key Speed

MIDI velocity curves act as mathematical transfer functions that redefine how the physical speed of a key press translates into an output velocity value between 0 and 127. When a musician strikes a key, hardware sensors measure the transit time of that strike to determine physical velocity. By applying different mathematical formulas—such as linear, exponential, logarithmic, or polynomial functions—to this input, velocity curves shift the dynamic response to accommodate different playing techniques, keyboard actions, and virtual instrument behaviors.

Physical Measurement: From Time to Raw Velocity

Modern MIDI controllers typically use two or three contact switches (or optical sensors) positioned beneath each key. When a key is depressed, an internal microprocessor measures the elapsed time (\(\Delta t\)) between the activation of the first and second switches.

Because velocity is the rate of displacement over time (\(v = d / \Delta t\), where \(d\) is the fixed distance between sensors), raw physical speed is inversely proportional to elapsed time. A shorter interval represents a faster, harder strike, while a longer interval indicates a soft strike. Before applying a velocity curve, the firmware normalizes this raw time value into an internal input variable, typically represented as a normalized floating-point number \(x\) in the range of \([0.0, 1.0]\).

The Linear Baseline Mapping

In a direct linear implementation, the normalized input \(x\) is mapped to the standard 7-bit MIDI range (0–127) using a basic scale-and-offset function:

\[\text{MIDI Output} = \text{clamp}(\text{round}(127 \times x), 0, 127)\]

Under this linear baseline, changes in physical strike speed produce proportional changes in the output value. A 10% increase in physical speed results in a 10% increase in MIDI velocity. However, human hand mechanics do not exert force linearly across dynamic ranges, often making pure linear response feel stiff or unresponsive.

Non-Linear Velocity Curve Types

To modify the instrument's dynamic response, velocity curves apply mathematical transformations to the normalized input \(x\) before scaling to the 0–127 range. Most curves rely on power functions, logarithmic mappings, or sigmoidal algorithms:

  • Exponential Curves (Hard Response): Defined generally as \(f(x) = x^\gamma\) where \(\gamma > 1\). By applying an exponent greater than one, the mathematical curve curves downward initially. Lower and moderate strike speeds produce low MIDI output values, requiring significantly more physical force to reach higher velocities. This setting benefits players with a heavy touch who frequently trigger maximum velocities inadvertently.
  • Logarithmic Curves (Soft Response): Defined as \(f(x) = x^\gamma\) where \(0 < \gamma < 1\), or through scaled logarithmic expressions such as \(f(x) = \frac{\ln(1 + kx)}{\ln(1 + k)}\). The curve rises steeply at low input levels and flattens toward the maximum threshold. Small physical forces yield rapid gains in output value, allowing light-touch players to reach loud dynamics without striking the keybed aggressively.
  • S-Curves (Sigmoidal Response): Implemented via cubic Hermite curves or logistic functions, S-curves suppress sensitivity at the extreme low and extreme high ends while maximizing sensitivity in the middle range. This configuration provides fine-grained expressive control over mezzo-piano and mezzo-forte playing while preventing accidental drops to near-zero or sudden jumps to 127.

Implementation via Lookup Tables (LUTs)

In embedded microcontroller systems with limited computing cycles, calculating continuous power or logarithmic equations in real time introduces latency. Instead of running high-overhead calculations per key strike, hardware and software engines pre-calculate the mathematical curve into an array known as a Lookup Table (LUT).

The raw input velocity directly indexes into the array, which instantly returns the mapped integer value between 0 and 127:

\[\text{Output} = \text{LUT}[\text{Raw Index}]\]

This table-driven approach allows complex, multi-segment, or user-drawn polynomial curves to be evaluated in constant time, transforming the mechanical reality of key strikes into tailored digital dynamics with zero perceptible lag.
