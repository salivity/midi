Live Touring Dual-Computer MIDI Failover Switching

In modern arena-level concert tours, audio and MIDI playback failure is not an option. To guarantee uninterrupted performances, playback engineers build fully redundant, dual-computer rigs—commonly designated as System A (Primary) and System B (Redundant). This article breaks down the architecture of these touring rigs, detailing how playback engineers synchronize duplicate systems, use continuous heartbeat monitoring to detect system failure, and deploy hardware-based automatic failover switches to instantly transfer MIDI control to the backup machine without dropping a beat.

System Topology: Rig A and Rig B

A redundant touring setup centers around two identical computers running matching digital audio workstations (DAWs), typically Ableton Live, Apple MainStage, or Pro Tools. Every virtual instrument, software patch, MIDI clip, and external routing parameter is precisely mirrored between the machines.

Both computers receive the exact same controller inputs simultaneously. When a keyboardist plays an arena stage, the master keyboard's MIDI output connects to a hardware splitter (or an RTP-MIDI network interface) that routes identical incoming performance data into both System A and System B concurrently. Consequently, both systems continuously process and generate identical MIDI data in the background.

Playback Synchronization

For timed automation—such as program changes for guitar modelers, keyboard patch shifts, and lighting or video triggers—both DAWs must run in exact alignment. Engineers achieve this through two primary methods:

  • Simultaneous Playback Triggers: Hardware transport controllers (such as those from JLCooper or custom MIDI controllers) send a single "Play" and "Stop" command simultaneously over a split connection to both computers.
  • Master-Slave Synchronization: One machine acts as the timecode master, sending MIDI Timecode (MTC) or SMPTE LTC to the second machine. While effective, many modern playback technicians prefer fully decoupled, simultaneously triggered systems to prevent an issue on Rig A from corrupting Rig B's playback timeline.

Heartbeat Detection and Failover Triggers

To switch from Rig A to Rig B instantly, the system needs an automated mechanism to detect when the primary machine has frozen, crashed, or suffered a disconnected cable. This is achieved using a continuous "heartbeat" signal.

Most professional auto-switchers use an audio tone (such as a continuous 20 kHz ultrasonic pitch, an inaudible sub-frequency, or a standard 1 kHz tone routed away from the main mix) output by Rig A. Alternatively, some modern systems monitor a continuous stream of MIDI clock or control change (CC) pulses.

As long as the hardware switcher detects the continuous heartbeat from Rig A, it keeps the Rig A signal paths open to front-of-house (FOH) and the stage. If Rig A crashes, the audio/MIDI stream freezes, the heartbeat drops, and the switcher triggers an automatic swap within milliseconds.

Hardware Failover Switchers

Hardware auto-switchers serve as the central hub of the redundant rig. These specialized rack units receive audio and MIDI connections from both computers and provide a single output destination for the rest of the tour's infrastructure.

  • Integrated Audio/MIDI Switchers: Units like the iConnectivity PlayAUDIO series handle both multi-channel audio and multi-stream MIDI over USB. The device connects directly to both computers via dual USB interfaces. When a failure is detected, the unit's onboard microcontrollers seamlessly switch the routing logic from USB Port A to USB Port B.
  • Modular Switchers: Analogous setups use dedicated MIDI switchers (such as those from Radial Engineering or custom MIDI solutions) slaved to an audio switcher (like the Radial SW8). When the master audio switcher detects a lost tone and activates the switch, it sends a control voltage (CV) pulse to the linked MIDI switcher, triggering an instantaneous, mechanical or digital relay swap for all MIDI lines.

Because the switch happens in a fraction of a second, the backup machine takes over mid-stream. If notes are currently sustaining during a switch, modern MIDI switchers or DAW scripts transmit an immediate "All Notes Off" (CC 123) command to prevent stuck notes before resuming regular data transmission.

MIDI Distribution to the Stage

Once the active signal exits the switcher, it is distributed across the arena production environment:

  1. DIN and TRS MIDI: For local stage equipment like keyboard racks, drum sound modules, and guitar pedalboards, MIDI data is passed through high-grade MIDI distribution amplifiers (thru boxes) over balanced 5-pin DIN or TRS runs.
  2. Network MIDI (RTP-MIDI): For long-distance arena runs to lighting consoles (grandMA), video servers (Resolume/Disguise), and automated backline stations, systems convert the post-switch MIDI output into RTP-MIDI over standard Gigabit Ethernet networks. This eliminates the latency and 50-foot distance limits of traditional 5-pin MIDI cabling.

Best Practices for Redundant Touring Operation

  • Isolated USB Buses: Engineers run dedicated, enterprise-grade USB hubs with isolated buses to prevent peripheral draw issues from crashing the computer's internal controller.
  • Uninterruptible Power Supplies (UPS): Both computers and all network/switching hardware are powered by separate, line-interactive battery backup systems to guard against stage power surges or drops.
  • Dedicated OS Optimization: Both touring computers run stripped-down operating systems with all wireless connectivity, system updates, sleep modes, and non-essential background processes permanently disabled.
