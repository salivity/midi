What Is a MIDI Song Select Message 0xF3?

The MIDI Song Select message (0xF3) is a specialized System Common message used to remotely cue and load pre-programmed songs, patterns, or arrangements in external hardware. Unlike standard patch-changing messages that alter individual instrument sounds, Song Select directs an entire device to load a specific sequence into its active playback buffer. This article explains the technical structure of the 0xF3 message and details how hardware drum machines interpret it to recall stored rhythm sequences.

Understanding the 0xF3 Message Structure

In the MIDI 1.0 specification, messages are divided into categories such as Channel Voice, System Real-Time, and System Common. Song Select belongs to the System Common category, meaning it is not bound to a specific MIDI channel (1–16). Instead, it communicates globally with any receiving device capable of sequence playback.

The message consists of two bytes:

  1. Status Byte (0xF3): In hexadecimal notation, 0xF3 (binary 11110011, or 243 in decimal) alerts the receiving device that a Song Select command is arriving.
  2. Data Byte (0x00 to 0x7F): A single 7-bit data byte directly follows the status byte, providing a value between 0 and 127 in decimal. This number identifies the target sequence, pattern, or song index to be loaded.

Because the data byte is 7-bit, a single 0xF3 message can address up to 128 discrete songs or sequences (numbered 0 through 127).

Song Select vs. Program Change

While both messages recall saved data, they serve different functional layers:

  • Program Change (0xCn): A Channel Voice message that changes the sound preset, patch, or kit on a specific MIDI channel without changing the sequencer arrangement.
  • Song Select (0xF3): A global command that instructs the device's internal sequencer to change the entire active musical sequence or song layout.

How It Loads Sequences on External Drum Machines

Modern and vintage drum machines—such as those manufactured by Roland, Elektron, Akai, or Alesis—often feature onboard step sequencers that store discrete "Patterns" or chained "Songs." When an external master controller (such as a DAW, hardware master sequencer, or MIDI pedalboard) transmits a Song Select command, the drum machine processes the request through the following steps:

  1. Reception and Filtering: The drum machine receives the incoming serial MIDI stream. If its MIDI settings have System Common messages enabled, it identifies 0xF3 and reads the subsequent data byte.
  2. Index Mapping: The drum machine maps the value of the data byte to its internal memory structure. Depending on the machine’s architecture, this value corresponds to an internal Song memory location (e.g., Song 01 to Song 128) or, on some devices, a direct Pattern bank slot (such as Pattern A01 through H16).
  3. Buffer Loading: The drum machine unloads the current pattern from memory and loads the designated sequence into its active playback queue. The sequencer resets its internal playhead to beat one, measure one of the chosen sequence.
  4. Synchronization and Playback: Loading a sequence via 0xF3 does not automatically start playback. Typically, the master device sends 0xF3 while the transport is stopped to give the drum machine time to fetch the pattern data. Once loaded, the master sends MIDI Clock (0xF8) pulses to establish tempo, followed by a MIDI Start message (0xFA) to trigger the newly loaded sequence in tight synchronization with the rest of the rig.
