AUv3 Polyphonic MIDI Routing in Mobile DAWs

Apple’s Audio Unit v3 (AUv3) framework handles polyphonic MIDI routing and generation through a standardized, low-latency API designed for inter-process communication (IPC) between plugins and host applications on iOS, iPadOS, and macOS. By utilizing real-time render blocks, multi-bus architecture, and support for both classic MIDI and modern protocols like MIDI 2.0 and MIDI Polyphonic Expression (MPE), AUv3 allows mobile digital audio workstations (DAWs) to route sample-accurate, multi-voice performance data across complex virtual studio configurations.

Real-Time Event Blocks and Scheduling

AUv3 separates the user interface from the audio processing engine by hosting the plugin in an external process extension. Inside the audio render cycle, MIDI data does not travel over standard system inter-process notifications; instead, it is handled in a real-time audio thread using specialized C-based blocks.

When generating polyphonic data, an AUv3 MIDI generator or MIDI FX plugin uses the MIDIOutputEventBlock. This block delivers timestamped events directly to the host's render cycle. Conversely, an instrument receiving polyphonic data processes incoming notes via the scheduleMIDIEventBlock or modern scheduleMIDIEventListBlock. Each polyphonic voice—consisting of discrete Note On, Note Off, Polyphonic Key Pressure (Aftertouch), and controller events—is tagged with a sample offset relative to the current audio buffer start time. This sample-accurate timestamping ensures that polyphonic chords trigger simultaneously without timing jitter, regardless of the buffer size used by the host DAW.

Multi-Bus Architecture for MIDI Routing

AUv3 defines MIDI capabilities through explicit input and output bus arrays (AUAudioUnitBusArray). While standard audio units focus on audio channel configurations, MIDI-capable units define their logical MIDI inputs and outputs:

  1. MIDI Processors and Generators: Plugins declare one or more MIDI output ports. This enables generators (such as polyphonic sequencers, chord engines, or arpeggiators) to transmit multiple voices to downstream tracks or other plugins.
  2. Multi-Timbral and Multi-Bus Instruments: AUv3 instruments can expose multiple MIDI input busses. A host can route separate polyphonic streams from different tracks into a single AUv3 instance, addressing specific MIDI channels or independent busses to trigger distinct multi-sampled or synthesized layers.

DAWs such as Logic Pro for iPad, AUM, Cubasis, and Loopy Pro intercept these output blocks and dynamically bridge them to the input blocks of downstream AUv3 instruments.

MIDI Polyphonic Expression (MPE) and Channel Allocation

Traditional MIDI 1.0 sends channel-wide control changes (such as Pitch Bend or Mod Wheel), which affect all sounding voices uniformly. To handle polyphonic articulation, AUv3 natively supports MPE configurations.

In an MPE workflow within an AUv3 environment:

  • The host or generating plugin allocates a master channel (typically Channel 1 or 16) for global controls.
  • Individual voices are dynamically assigned their own individual MIDI channels (Channels 2–15).
  • Per-note pitch bends, pressure, and CC74 (slide/timbre) messages are generated and routed alongside Note On messages on those dedicated voice channels.

The AUv3 host receives the generated stream from the sender's MIDIOutputEventBlock and delivers it intact to the target AUv3 synthesizer, preserving the per-voice modulation data across the entire polyphonic chord.

Modern Implementation: MIDI 2.0 and Universal MIDI Packets (UMP)

Recent iterations of the AUv3 specification integrate Universal MIDI Packets (UMP) through the AUMIDIEventListBlock. This modernization improves polyphonic generation in several ways:

  • High-Resolution Velocity and Controllers: Instead of the 7-bit limits (0–127) of legacy MIDI, UMP provides 16-bit or 32-bit resolution for note velocity and articulation, allowing AUv3 polyphonic generators to output extremely granular dynamic data.
  • Native Per-Note Controllers: MIDI 2.0 introduces native per-note pitch and per-note assignable controllers without requiring the multi-channel overhead of MPE.
  • Unified Protocol Handling: The host DAW can pass UMP data directly between plugins, avoiding continuous translations between legacy byte streams and internal DAW parameter representations.

Through the combination of sample-accurate event scheduling, multi-bus infrastructure, and low-overhead block communication, the AUv3 specification provides mobile DAWs with the performance and precision required for advanced polyphonic generation and complex signal routing.
