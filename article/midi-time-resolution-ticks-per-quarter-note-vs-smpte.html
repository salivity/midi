MIDI Time Resolution: Ticks Per Quarter Note vs SMPTE

A Standard MIDI File (SMF) defines its timing resolution using a dedicated 16-bit field called division, located in the header chunk (MThd). This setting dictates how delta-time values between MIDI events are interpreted by software or hardware sequencers. The file format supports two distinct timing modes: metrical time based on ticks per quarter note, which ties resolution to musical tempo, and absolute time based on the SMPTE (Society of Motion Picture and Television Engineers) standard, which ties resolution to fixed real-world clock time.

The Header division Field

The division parameter occupies the final two bytes of the standard 14-byte MThd chunk. The interpretation of these 16 bits is determined entirely by the most significant bit (bit 15). Software reading the file checks this bit to decide whether the time base is metrical or timecode-based.

Metrical Timing: Ticks Per Quarter Note (PPQN)

When bit 15 of the division word is set to 0, the file uses metrical time. In this mode, the remaining 15 bits (bits 0 through 14) represent an unsigned integer that specifies the number of clock ticks per quarter note, often abbreviated as TPQN or PPQN (pulses per quarter note).

  • Format: A positive 16-bit integer ranging from 1 to 32,767. Common historical values include 96, 120, 240, 480, and 960.
  • Behavior: Delta times in this format are musical, not absolute. The real-world duration of each tick fluctuates depending on the current tempo of the sequence. If the sequence contains a "Set Tempo" meta-event (specifying microseconds per quarter note), the duration of a single tick is calculated as: \[\text{Tick Duration} = \frac{\text{Microseconds per Quarter Note}}{\text{Ticks per Quarter Note}}\]
  • Application: This is the default format for standard musical compositions, as it allows tempo changes, rubato, accelerando, and ritardando without requiring recalculation of every note's delta time.

Absolute Timing: SMPTE Units

When bit 15 of the division word is set to 1, the file uses absolute, wall-clock time referencing the SMPTE timecode standard. In this mode, the 16-bit value is split into two separate 8-bit signed and unsigned bytes.

  • High Byte (SMPTE Format): Bits 8 through 15 represent the SMPTE frame rate stored as a negative two's complement integer. The standard values are:
    • -24 (0xE8): 24 frames per second (standard film)
    • -25 (0xE7): 25 frames per second (PAL/SECAM video)
    • -29 (0xE3): 29.97 frames per second (NTSC drop-frame video)
    • -30 (0xE2): 30 frames per second (NTSC non-drop video)
  • Low Byte (Ticks Per Frame): Bits 0 through 7 represent an unsigned 8-bit integer specifying the resolution within each frame (sub-frame divisions). Common values include 4, 8, 40, or 80 ticks per frame. A configuration of 30 frames per second with 80 ticks per frame yields a resolution of 2,400 ticks per second.
  • Behavior: Ticks represent a fixed interval of real-world time. The duration of each tick is constant and immune to MIDI tempo meta-events.
  • Application: SMPTE-based timing is typically utilized in film scoring, television post-production, and audio-video synchronization, where events must align precisely with visual cues regardless of musical structure.
