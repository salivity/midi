What Is the MIDI Sample Dump Standard (SDS)?

The MIDI Sample Dump Standard (SDS) is an extension of the original MIDI 1.0 specification that enables the bidirectional transfer of raw digital audio waveform data between musical instruments, samplers, and computers. Introduced in the late 1980s, SDS established a manufacturer-agnostic protocol for transmitting Pulse Code Modulation (PCM) samples over traditional 5-pin DIN MIDI serial cables. While inherently slow due to MIDI’s modest transmission rate, SDS solved interoperability challenges by defining standardized sample headers, data packetization, bit-depth adaptation, and closed-loop handshaking protocols.

The Underlying Transmission Bottleneck

Standard MIDI operates as an asynchronous serial connection running at a fixed rate of 31.25 kbaud (31,250 bits per second), utilizing 1 start bit, 8 data bits, and 1 stop bit (10 bits total per frame). This yields an effective maximum throughput of 3,125 bytes per second.

Because uncompressed PCM audio contains thousands of bytes per second—such as a 16-bit, 44.1 kHz mono sample requiring 88,200 bytes per second—transmitting audio over MIDI cannot happen in real time. Instead, SDS is an offline, non-real-time file transfer protocol designed purely for data fidelity rather than playback performance.

Overcoming the 7-Bit Data Limitation

A primary technical hurdle of transmitting raw PCM over MIDI is the MIDI byte architecture:

  • Status Bytes: Values from 128 to 255 (binary 10000000 to 11111111) are reserved exclusively for MIDI command definitions.
  • Data Bytes: Values from 0 to 127 (binary 00000000 to 01111111) are the only bytes permitted to carry payload data, meaning the most significant bit (MSB) must always be 0.

Raw binary PCM data frequently uses bytes exceeding value 127. If sent raw, the receiving instrument would misinterpret sample data as MIDI status messages (such as Note On or Clock ticks).

To circumvent this, SDS encapsulates audio inside MIDI System Exclusive (SysEx) messages and repackages raw PCM samples into 7-bit streams. Depending on the original sample resolution (SDS supports depths from 8 to 28 bits):

  • An 8-bit sample is split across two 7-bit MIDI bytes.
  • A 16-bit sample is split across three 7-bit MIDI bytes.
  • Higher-resolution samples are similarly encoded using left-justified bit packing.

This bit-shifting adds roughly 14% to 50% data overhead, reducing the already limited throughput, but it guarantees that sample data never violates MIDI protocol rules.

The SDS Communication Architecture

The SDS protocol establishes transmission through two main packet types: the Dump Header and Dump Data Packets.

1. The Dump Header

Before transmitting any waveform data, the sending device transmits a SysEx Header packet containing the metadata necessary for the receiver to allocate memory and configure playback:

  • Sample Number: Identifies which sample slot or patch is being written.
  • Sample Resolution: Specifies bit depth (8 to 28 bits).
  • Sample Rate: Defined in nanoseconds per sample period to maintain absolute timing accuracy.
  • Sample Length: Total word count of the audio file.
  • Loop Points: Start and end markers for sustained playback loops, including loop type (forward or alternating).

2. Dump Data Packets

Once the header is accepted, the PCM audio is sent sequentially in discrete packets:

  • Each packet contains an index counter (modulo 128) to track order.
  • The audio data payload is fixed at 120 bytes per packet.
  • Each packet concludes with an exclusive-OR (XOR) checksum calculation to evaluate data integrity across the serial line.

Handshaking and Error Correction

Because hardware buffers in early digital samplers were small and prone to overrun, SDS supports two operational modes: open-loop (simplex) and closed-loop (duplex).

  • Open-Loop Mode: Uses a single MIDI cable from the sender to the receiver. The sender transmits packets blindly, often with artificial pauses between packets to prevent buffer overflow. There is no error correction; dropped bytes result in corrupted audio.
  • Closed-Loop Mode: Uses two MIDI cables to form a bidirectional loop. This enables hardware handshaking via small SysEx command messages:
    • ACK (Acknowledge): Confirms that a packet arrived without checksum errors and the receiver is ready for the next one.
    • NAK (Negative Acknowledge): Signals a checksum mismatch, prompting the sender to retransmit the corrupted packet.
    • CANCEL: Aborts the transfer entirely.
    • WAIT: Instructs the sender to pause while the receiver processes data, writes to flash memory, or clears internal buffers.

Through this structured packetization, bit-level reformatting, and explicit verification, the MIDI Sample Dump Standard allowed early digital musicians and sound designers to reliably back up, edit, and interchange digital waveforms across disparate synthesizer platforms.
