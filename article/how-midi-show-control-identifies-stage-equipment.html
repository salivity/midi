How MIDI Show Control Identifies Stage Equipment

MIDI Show Control (MSC) relies on a standardized Universal System Exclusive (SysEx) messaging structure to synchronize live entertainment technologies such as lighting, audio, and stage machinery. This article explains how an MSC command string pinpoints and isolates specific equipment categories using the dedicated Command Format byte, how these values map to different stage disciplines, and how receiving devices evaluate these identifiers to ensure cue commands execute reliably across complex network setups.

The MSC Message Structure

A standard MIDI Show Control command is embedded inside an open-loop Real Time Universal System Exclusive packet. The raw byte sequence follows a fixed order:

F0 7F [Device ID] 02 [Command Format] [Command] [Data] F7

  • F0: System Exclusive start byte.
  • 7F: Universal Real Time System Exclusive header.
  • [Device ID]: Identifies the targeted physical device or group.
  • 02: The MSC sub-ID, signifying that the packet contains Show Control data.
  • [Command Format]: The byte specifying the category of equipment being instructed.
  • [Command]: The actual action (e.g., GO, STOP, RESUME).
  • [Data]: Optional cue numbers, cue lists, or times.
  • F7: End of System Exclusive byte.

The Command Format Byte

The primary mechanism for distinguishing between different types of stage hardware is the Command Format byte (cmd_fmt). This single byte directly defines the discipline or function of the intended receiver.

When a master show controller issues an MSC message, every device connected to the MIDI line reads the incoming stream. A target machine checks the Command Format byte against its internal profile. If the byte does not match the device's assigned operational category, the message is ignored.

Standard Equipment Category Allocations

The MIDI Show Control specification organizes hardware into distinct functional ranges using hexadecimal values:

  • Lighting (01–0F): 01 denotes general lighting consoles; sub-allocations include values like 02 for moving lights and 03 for color changers.
  • Sound (10–1F): 10 addresses general sound hardware; sub-allocations designate playback systems (11), sound reinforcement (12), and spatial audio processors.
  • Machinery and Rigging (20–2F): 20 targets general stage automation, including fly systems, revolves, stage lifts, and winches.
  • Video (30–3F): 30 addresses media servers and video playback equipment.
  • Projection (40–4F): 40 specifies projection hardware, including shutters and display systems.
  • Process Control and Special Effects (50–5F): 50 controls physical effects, including pyrotechnics, atmospheric smoke, haze, and hydraulic actuators.
  • All-Types (7F): A universal broadcast category that instructs all connected equipment types to execute the command simultaneously, regardless of their discipline.

Discrimination via Device ID and Command Format

The Command Format operates in tandem with the Device ID byte to establish a granular addressing hierarchy:

  1. Individual Device Match: A sound console set to Device ID 05 and format 10 (Sound) only reacts if both fields align.
  2. Category Broadcast: If the Device ID is set to 7F (all devices) but the Command Format is set to 01 (Lighting), every lighting desk on the network fires the cue, while all sound and automation hardware discard the packet.
  3. Universal Broadcast: Setting both the Device ID and Command Format to 7F forces an emergency global command (such as an all-stop) across every piece of stage gear listening to the chain.
