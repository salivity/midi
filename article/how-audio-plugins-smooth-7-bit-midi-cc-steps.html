How Audio Plugins Smooth 7-Bit MIDI CC Steps

Standard MIDI Continuous Controller (CC) messages transmit values using a 7-bit integer range from 0 to 127, which frequently causes audible "zipper noise" and stepping artifacts when adjusting sensitive parameters like filter cutoffs or gain levels. To resolve this, digital audio plugins implement real-time parameter smoothing using techniques such as linear interpolation, low-pass filtering, and slew-rate limiting. These algorithms translate low-resolution control messages into high-resolution, sample-accurate modulation streams, bridging the gap between discrete control data and continuous audio signals.

The Cause of Stepped Audio Artifacts

The core issue stems from the disparity between MIDI data rates and digital audio sample rates. With only 128 discrete values, mapping a 7-bit message to a wide dynamic range produces massive jumps. For instance, mapping 0–127 across a logarithmic frequency range from 20 Hz to 20,000 Hz means a single CC increment can alter the frequency by hundreds of Hertz instantly. When an audio parameter abruptly changes value between two adjacent audio samples, the sudden discontinuity introduces high-frequency energy into the signal, perceived by listeners as clicks, pops, or a coarse "zipper" sound.

One-Pole Low-Pass Filtering (Leaky Integrators)

The most common internal method for parameter smoothing is a single-pole Infinite Impulse Response (IIR) low-pass filter, often implemented as an exponential smoothing algorithm. Instead of jumping immediately to a new target value, the plugin updates the internal parameter on a per-sample basis using a weighted average of the current value and the incoming target:

\[y[n] = y[n-1] + \alpha \cdot (x[n] - y[n-1])\]

In this equation, \(x[n]\) represents the target MIDI value (normalized or mapped to the target parameter scale), \(y[n]\) is the smoothed output value applied to the audio processing loop, and \(\alpha\) is a smoothing coefficient calculated from a designated time constant (typically between 5 to 50 milliseconds) relative to the sample rate. This ensures an asymptotically smooth transition toward the target value without sudden steps.

Linear and Polynomial Interpolation

Another widely used technique, particularly within block-based audio architectures, is linear ramp interpolation. Digital audio workstations (DAWs) process audio in blocks or buffers (e.g., 64, 128, or 512 samples). When a new MIDI CC message arrives within a buffer:

  1. The plugin notes the starting parameter value at sample 0 of the block.
  2. It sets the destination value based on the incoming MIDI message.
  3. It calculates a step delta: \(\text{Delta} = (\text{Target} - \text{Current}) / N\), where \(N\) is the number of samples over which the transition should occur.
  4. The plugin increments the parameter value by this fractional delta at every sample calculation.

For more natural modulation behavior—such as simulating analog potentiometer resistance or non-linear human hearing—plugins often employ polynomial, logarithmic, or S-curve interpolation to avoid mechanical-sounding linear sweeps.

Slew-Rate Limiting

Slew-rate limiters smooth incoming signals by enforcing a strict maximum rate of change per unit of time (\(dV/dt\)). If a user moves a MIDI controller knob violently, the incoming data creates steep value differentials. A slew limiter permits the parameter to follow the incoming value exactly, provided the change per sample remains below a pre-set threshold. If the incoming change exceeds that threshold, the parameter only increases or decreases by the maximum allowed delta per sample until it catches up to the target. This eliminates instant jumps while preserving maximum responsiveness for slow, deliberate movements.

Framework Implementations and Native De-Zippering

Modern plugin development frameworks automate these processes through built-in parameter smoothing classes. For example, JUCE provides the juce::SmoothedValue class, which allows developers to configure either linear ramping or exponential smoothing over a specified duration in seconds or sample counts.

Under the hood, these modern engines convert incoming 7-bit MIDI CC values immediately into 32-bit or 64-bit floating-point numbers. Once normalized, the smoothing engine updates the parameter at the full audio sample rate (e.g., 44.1 kHz or 96 kHz) or at a slightly downsampled control rate (e.g., every 8 or 16 samples). By continuously updating the DSP coefficients at audio rate rather than control rate, plugins completely eliminate zipper noise and deliver continuous, analog-style parameter sweeps.
