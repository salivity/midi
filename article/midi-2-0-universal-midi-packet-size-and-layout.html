MIDI 2.0 Universal MIDI Packet Size and Layout

This article covers the structural architecture of the Universal MIDI Packet (UMP) format introduced in the MIDI 2.0 standard, with a specific focus on word sizing and data capacity. In the MIDI 2.0 Universal MIDI Packet specification, messages are arranged in variable lengths of 32-bit units. The maximum packet size defined within the standard UMP layout is four total 32-bit words (128 bits in total).

Universal MIDI Packet Architecture

The Universal MIDI Packet (UMP) serves as the foundational data container for both MIDI 1.0 protocol messages and MIDI 2.0 protocol messages. Unlike the byte-stream approach of legacy MIDI, all UMP data is strictly organized into 32-bit boundaries.

Every UMP begins with a 4-bit Message Type (MT) field located in bits 31–28 of the first 32-bit word. This MT field dictates both the function of the message and the total length of the packet.

Packet Length Variations

A Universal MIDI Packet can span across one, two, three, or four 32-bit words depending on the Message Type:

  • 1 Word (32 bits / 4 bytes): Used for Utility Messages, System Real-Time messages, System Common messages, and legacy MIDI 1.0 Channel Voice Messages.
  • 2 Words (64 bits / 8 bytes): Used for standard MIDI 2.0 Channel Voice Messages, 64-bit data messages, and 7-bit System Exclusive (SysEx7) transfers.
  • 3 Words (96 bits / 12 bytes): Reserved for extended message formats and future expansion.
  • 4 Words (128 bits / 16 bytes): Used for Extended Data Messages, such as 8-bit System Exclusive (SysEx8) and Mixed Data Set (MDS) payloads.

The Maximum Packet Size

The architecture caps an individual packet at four 32-bit words (128 bits). Any transaction requiring larger continuous data streams, such as bulk transfers or high-resolution sample dumps, splits the payload across multiple consecutive four-word packets labeled with start, continue, and end status flags. Consequently, network and transport layers implementing MIDI 2.0 only need to allocate buffers capable of handling up to 128 bits per discrete packet transaction.
