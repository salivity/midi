Using MIDI to Trigger Multitrack Audio in QLab

Theatrical sound designers frequently use QLab to automate complex soundscapes by configuring incoming MIDI note messages to trigger synchronized, multitrack audio cues. This integration allows external hardware, such as digital audio workstations, synthesizers, lighting desks, or show control systems, to seamlessly drive playback without requiring manual operation at the sound console. By routing incoming MIDI commands to specific cue targets mapped across multichannel outputs, productions achieve precise, frame-accurate synchronization essential for modern live performance.

Establishing the MIDI Connection

The workflow begins by establishing a hardware or network MIDI path between the sending device and the primary playback computer running QLab. Common physical connections include standard 5-pin DIN cables connected to an external audio/MIDI interface, direct USB-MIDI connections, or network-based RTP MIDI (AppleMIDI) sent over local Ethernet networks.

Once the physical or network interface is connected to the macOS system, QLab detects the port in its Workspace Settings under the MIDI controls. Designers define specific MIDI patch inputs here to ensure that incoming messages from designated controllers are appropriately identified.

Building Multitrack Audio Cues

Before mapping triggers, the designer organizes the audio assets within the workspace:

  1. Audio Patching: The designer configures an audio patch linking QLab to a multichannel audio interface (such as a Dante, AVB, or multi-out USB/Thunderbolt interface).
  2. Cue Structuring: To handle multitrack playback, designers typically use either a single interleaved multitrack audio file (such as a 6-channel or 8-channel WAV) or multiple individual audio cues placed inside a Group Cue.
  3. Timeline Synchronization: When using a Group Cue containing separate stems, the mode is set to "Start all children simultaneously" (Timeline Mode). This guarantees that every individual track—dialogue stems, localized sound effects, and musical underscoring—plays back in exact sample synchronization.
  4. Channel Matrix Routing: In the cue's "Audio Levels" tab, each track is assigned to its respective physical output channel to distribute audio correctly to stage monitors, surround arrays, or the main sound reinforcement system.

Mapping Incoming MIDI Notes to Cues

To enable automated triggering, QLab allows any individual cue or group cue to listen for a discrete MIDI message.

  1. Select the Cue: The designer selects the target Group Cue or single multitrack Audio Cue in the cue list.
  2. Access Triggers: In the lower inspector pane, navigate to the Triggers tab.
  3. Enable MIDI Trigger: Check the box labeled "MIDI Trigger."
  4. Capture the Note: QLab provides a "Capture" button. When active, sending a physical MIDI note from the external source automatically populates the required fields: message type (Note On), MIDI channel (1–16), note number (0–127), and velocity parameters. Alternatively, these values can be set manually.
  5. Velocity Handling: Designers typically configure the trigger to accept "any" velocity (greater than 0) rather than a fixed velocity value. This ensures the cue triggers reliably regardless of variations in strike intensity if played from a live MIDI controller like a drum pad or keyboard.

Playback Execution and Live Control

When the external device sends the specified Note On command, QLab processes the event with minimal latency. The command bypasses the standard manual "GO" sequence, firing the mapped multitrack cue instantly.

Designers often utilize additional MIDI messages to manage playback states. For example, a secondary Note On event on a different pitch can be captured by a "Fade & Stop" cue targeting the playing audio, allowing the external show controller to smoothly terminate or fade multitrack tracks in response to onstage timing changes. This decoupled, event-driven architecture ensures consistent audio performance while remaining adaptable to live theatrical variation.
