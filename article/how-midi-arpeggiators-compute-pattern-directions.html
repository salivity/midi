How MIDI Arpeggiators Compute Pattern Directions

A MIDI arpeggiator transforms static chord input into dynamic melodic sequences by capturing held notes, sorting them mathematically by pitch, and stepping through them using clock-synchronized algorithms. This article breaks down the internal mechanics of a MIDI arpeggiator, exploring how incoming MIDI data is buffered, sorted, and translated into specific directional playback patterns such as Up, Down, Up/Down, and Random.

Note Capture and Buffer Management

When multiple keys are depressed on a MIDI controller, the device transmits simultaneous Note On messages, each containing a pitch number (0–127) and a velocity value. The arpeggiator does not immediately output these notes together. Instead, it catches these messages and registers them in a temporary memory buffer or array.

As long as the keys remain held—or sustained via a hold/latch function—their note numbers remain active inside this buffer. When a key is released, its corresponding Note Off message removes that pitch from the active list.

Array Sorting and Pitch Indexing

Once the active notes are collected in the buffer, the arpeggiator establishes an organized baseline. Because human players rarely strike keys at the exact same millisecond, the raw input order usually reflects timing discrepancies rather than harmonic structure.

To create predictable motion, the arpeggiator's firmware executes a sorting algorithm (such as quicksort or insertion sort) to arrange the active note numbers in ascending chromatic order. For example, if a player strikes a C major chord out of order (G4, C4, E4), the engine sorts the values numerically by their MIDI note values:

  • Index 0: 60 (C4)
  • Index 1: 64 (E4)
  • Index 2: 67 (G4)

If an octave range multiplier is engaged (e.g., +1 or +2 octaves), the arpeggiator mathematically duplicates the array, adding 12 or 24 semitones to each value, and re-sorts the expanded list into a larger linear array.

Clock Synchronization and Pointer Tracking

Playback timing is governed by a clock source, either internal or synchronized to an external MIDI clock via pulses per quarter note (PPQN). At every specified musical subdivision (such as 1/8th or 1/16th notes), the clock triggers an execution cycle.

The arpeggiator maintains an internal variable known as a pointer or index counter. When the clock fires, the arpeggiator reads the note stored at the current pointer index, outputs a Note On message, schedules a Note Off based on the defined gate length, and recalculates the pointer's position for the next step.

Algorithmic Pattern Logic

The chosen pattern determines the mathematical rule used to update the pointer index on each clock pulse:

  • Up Mode: The pointer begins at index 0 and increments by 1 on each step (pointer = pointer + 1). Once the pointer reaches the maximum index (n - 1), a modulo operation or conditional reset loops the pointer back to 0.
  • Down Mode: The pointer begins at the highest index (n - 1) and decrements by 1 on each step (pointer = pointer - 1). Upon reaching index 0, it resets to n - 1.
  • Up/Down (Inclusive vs. Exclusive): The engine tracks a directional state flag (ascending or descending). In Inclusive mode, the pointer increments to the top note, plays it, reverses the state flag, and plays the top note again as the first step downward. In Exclusive mode, conditional logic prevents the boundary notes from repeating: upon reaching index n - 1, the engine reverses direction immediately, setting the next step to n - 2.
  • Random Mode: Instead of sequential math, the engine uses a pseudo-random number generator (PRNG) to select an index on each clock pulse (pointer = random(0, n - 1)). Advanced arpeggiators often include algorithmic constraints to prevent the same index from generating twice consecutively, ensuring continuous melodic movement.

Through this combination of data buffering, numerical sorting, and index manipulation, an arpeggiator converts an unmoving chord into structured, real-time musical patterns.
