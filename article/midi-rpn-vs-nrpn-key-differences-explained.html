MIDI RPN vs NRPN: Key Differences Explained

In MIDI communication, Registered Parameter Numbers (RPN) and Non-Registered Parameter Numbers (NRPN) are methods used to extend the standard 7-bit Control Change (CC) space, allowing devices to transmit 14-bit parameter addresses and high-resolution data. While both protocols follow an identical four-part transaction structure—combining parameter selection, data entry, and parameter deselect—they fundamentally differ in their standardization and the specific Control Change messages used to address them.

Standardization and Scope

The primary conceptual difference between RPN and NRPN lies in parameter ownership:

  • RPN (Registered Parameter Number): These parameters are standardized and defined universally by the MIDI Manufacturers Association (MMA) and the Association of Musical Electronics Industry (AMEI). Because they are standard specifications, any MIDI device supporting an RPN will interpret it the same way. Common examples include Pitch Bend Sensitivity (RPN 0,0), Master Fine Tuning (RPN 0,1), and Master Coarse Tuning (RPN 0,2).
  • NRPN (Non-Registered Parameter Number): These parameters are manufacturer-specific and proprietary. Hardware and software developers use NRPNs to control unique internal synth engine features—such as filter resonance, oscillator wavetables, or envelope decay rates—without needing approval from the MMA. Because they are not standardized, NRPN values defined on one synthesizer will likely control completely different functions or be ignored entirely on another.

CC Message Allocation

Technically, the transaction process differs only by the specific MIDI Control Change (CC) numbers assigned to target the parameter:

  • RPN Selection: Uses CC 101 for the Parameter MSB (Most Significant Byte) and CC 100 for the Parameter LSB (Least Significant Byte).
  • NRPN Selection: Uses CC 99 for the Parameter MSB and CC 98 for the Parameter LSB.

Shared Data Transmission

Once the target parameter is selected—via either CC 101/100 or CC 99/98—the method used to change its value is identical for both RPN and NRPN:

  1. Data Entry MSB: CC 6 sets the coarse value of the selected parameter (values 0–127).
  2. Data Entry LSB: CC 38 sets the fine adjustment (values 0–127), enabling high-resolution 14-bit data (up to 16,384 values).
  3. Step Adjustments: CC 96 (Data Increment) and CC 97 (Data Decrement) can alter the current value up or down in discrete single-step units.

Transaction Reset (Null Parameter)

To prevent accidental parameter alteration by stray CC 6 or CC 38 messages, good practice dictates "closing" the transaction. This is done by sending the "Null" parameter:

  • For RPN transactions, send CC 101 with a value of 127, followed by CC 100 with a value of 127.
  • For NRPN transactions, send CC 99 with a value of 127, followed by CC 98 with a value of 127.
