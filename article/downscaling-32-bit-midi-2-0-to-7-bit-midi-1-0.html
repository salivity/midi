Downscaling 32-bit MIDI 2.0 to 7-bit MIDI 1.0

This article explains the standard downscaling algorithm prescribed by the MIDI 2.0 specification for translating high-resolution 32-bit continuous controller data to legacy 7-bit MIDI 1.0 values. It covers the specific mathematical operation, implementation details for hardware and software developers, and the design rationale behind bit truncation versus other scaling methods.

The Prescribed Downscaling Algorithm

According to the official MIDI 2.0 specification (Universal MIDI Packet and MIDI 2.0 Protocol), the conversion of 32-bit controller data to 7-bit resolution is performed through direct bit truncation—specifically by retaining the 7 Most Significant Bits (MSBs) and dropping the lower 25 bits.

In programming, this operation is executed using a logical right bit-shift:

MIDI_1_Value = MIDI_2_Value >> 25;

In standard arithmetic terms, this is equivalent to integer division by \(2^{25}\) (33,554,432) with the fractional remainder discarded:

\[\text{Value}_{7\text{-bit}} = \left\lfloor \frac{\text{Value}_{32\text{-bit}}}{33554432} \right\rfloor\]

Range Mapping and Extremes

Because the operation relies purely on the top 7 bits, boundary values are preserved accurately without risk of overflow:

  • Minimum: A 32-bit minimum of 0x00000000 right-shifted by 25 yields 0 (0x00).
  • Maximum: A 32-bit maximum of 0xFFFFFFFF right-shifted by 25 yields 127 (0x7F).

Every 7-bit discrete step corresponds to a block of \(2^{25}\) values in the 32-bit domain. For example, any 32-bit value from 0x00000000 to 0x01FFFFFF translates to 0, while any value from 0xFE000000 to 0xFFFFFFFF translates to 127.

Rationale Over Alternative Scaling Methods

The MIDI Manufacturers Association (MMA) and AMEI chose simple bit truncation over floating-point division or rounding algorithms for several practical reasons:

  1. Computational Efficiency: Bit-shifting requires a single processor instruction cycle on almost all digital signal processors (DSPs) and microcontrollers, minimizing latency in real-time translation bridges.
  2. Reversibility with Bit-Replication: When scaling up from 7-bit to 32-bit, MIDI 2.0 uses bit-replication (repeating the 7 bits into the lower positions until all 32 bits are filled). Downscaling via truncation cleanly strips these replicated bits, ensuring predictable round-trip conversions without value drift.
  3. No Overflow Risks: Rounding methods (such as adding an offset before division) can cause values near 0xFFFFFFFF to round up to 128, which is an illegal value in 7-bit MIDI protocols and would require additional clamping logic. Truncation inherently remains within the valid 0–127 index.
