MIDI Poly Key Pressure vs Channel Pressure

This article examines the fundamental structural differences between MIDI Polyphonic Key Pressure and MIDI Channel Pressure messages within the MIDI 1.0 specification. While both messages communicate aftertouch data to modulate sound based on physical key pressure, they differ entirely in their byte structures, message lengths, targeted addressing, and bandwidth demands. Understanding these architectural variances clarifies how MIDI transmits expressive performance data at the protocol level.

Status Byte Encoding

At the binary level, both messages belong to the MIDI Channel Voice category, combining a 4-bit message type (opcode) with a 4-bit channel identifier (0–15, representing channels 1–16). However, their identifier opcodes are distinct:

  • Polyphonic Key Pressure: Uses the 4-bit binary opcode 1010 (hexadecimal A). A status byte for this message ranges from 0xA0 to 0xAF depending on the target channel.
  • Channel Pressure: Uses the 4-bit binary opcode 1101 (hexadecimal D). A status byte for this message ranges from 0xD0 to 0xDF depending on the target channel.

Message Length and Byte Structure

The most significant structural distinction between the two messages is total length and data payload configuration.

Polyphonic Key Pressure (3 Bytes Total)

Polyphonic Key Pressure requires three bytes to execute because it must explicitly define which individual key is receiving pressure:

  1. Status Byte (1010nnnn): Declares the message type and MIDI channel.
  2. Data Byte 1 (0kkkkkkk): Specifies the key/note number (0–127), indicating which specific note is being pressed.
  3. Data Byte 2 (0vvvvvvv): Specifies the pressure amount/value (0–127) applied to that specific note.

Channel Pressure (2 Bytes Total)

Channel Pressure is a global message that affects all active notes on a specified channel simultaneously. Because it does not target specific note numbers, it requires only two bytes:

  1. Status Byte (1101nnnn): Declares the message type and MIDI channel.
  2. Data Byte 1 (0vvvvvvv): Specifies the single aggregate pressure value (0–127) applied across the entire channel.

Addressing and Targeting Architecture

The difference in data byte count reflects fundamentally different targeting models:

  • Individual Note Targeting: Polyphonic Key Pressure couples a pressure value directly to a note number within the data stream. This creates an isolated control stream for every depressed key, allowing independent modulation for individual voices within a chord.
  • Monophonic/Global Targeting: Channel Pressure omits the note number byte entirely. Synthesizers interpret this message as a single, uniform modifier applied equally to all sounding voices assigned to that MIDI channel, typically responding to whichever key is pressed hardest.

Bandwidth and Data Flow Differences

Because of its structural footprint, Polyphonic Key Pressure creates a substantially heavier data stream over standard 31.25 kbaud MIDI connections. Generating aftertouch for a four-note chord using Polyphonic Key Pressure transmits 12 bytes per update cycle (3 bytes × 4 notes). In contrast, Channel Pressure transmits only 2 bytes per update cycle for the entire chord, requiring roughly 83% less transmission data per cycle than the multi-note polyphonic alternative.
