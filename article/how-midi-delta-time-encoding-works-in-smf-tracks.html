How MIDI Delta-Time Encoding Works in SMF Tracks

Inside a Standard MIDI File (SMF), track chunks (MTrk) organize musical performances by sequencing commands chronologically without using absolute timestamps. Instead, every event is preceded by a value known as "delta-time," which dictates the amount of time elapsed since the preceding event. This article explains how delta-time is structured, how it leverages Variable-Length Quantity (VLQ) encoding to minimize file size, and how audio engines interpret these values to recreate accurate musical timing.

The Role of Delta-Time in Track Chunks

A Standard MIDI File track chunk consists of a 4-byte identifier (MTrk), a 4-byte chunk length, and a stream of paired elements: a delta-time followed immediately by an event (such as a Note On, Note Off, or Meta Event).

Unlike digital audio, which streams continuous samples, MIDI relies on instructions. Rather than tagging an instruction with an absolute timestamp like "play at tick 1920," the format uses relative timing. A delta-time indicates how many clock ticks the sequencer must wait after the previous event before executing the next one. If multiple events occur simultaneously—such as notes in a chord—the first event carries the elapsed delta-time from the previous moment, while the subsequent concurrent events each have a delta-time of zero. The very first event in a track chunk carries a delta-time measured from the start of the sequence, which is typically zero.

Variable-Length Quantity (VLQ) Encoding

To prevent wasting storage space, delta-times are not stored as fixed 16-bit or 32-bit integers. A fixed 32-bit integer would require four bytes for every single timing gap, even though most musical intervals fit into small numbers. SMF resolves this by utilizing Variable-Length Quantity (VLQ) encoding.

VLQ allows an integer to be represented using between one and four bytes, depending on its size:

  1. The 7-Bit Payload: Each byte in a VLQ value dedicates its lower 7 bits (bits 0 through 6) to the actual numeric data.
  2. The Continuation Bit: The most significant bit (MSB, bit 7) acts as a flag. If the MSB is 1, it signals that at least one more byte follows. If the MSB is 0, it marks the final byte of the delta-time value.

To decode a VLQ delta-time:

  • Read bytes sequentially.
  • Strip off bit 7 from each byte.
  • Shift the accumulated 7-bit values to the left by 7 bits for each subsequent byte.
  • Stop reading when a byte with an MSB of 0 is encountered.

Examples of VLQ Values:

  • 0 ticks: Represented in hexadecimal as 0x00 (binary 00000000). The MSB is 0, indicating a single-byte number with a value of 0.
  • 127 ticks: Represented as 0x7F (binary 01111111). The MSB is 0, marking the end of the byte.
  • 128 ticks: Represented as 0x81 0x00. In binary, this is 10000001 00000000. Stripping the MSBs leaves 0000001 and 0000000, which concatenate to 10000000 in binary, or 128 in decimal.
  • 16,383 ticks: Represented as 0xFF 0x7F. Stripping the MSBs leaves fourteen 1 bits, totaling 16,383.

The maximum permissible delta-time in the MIDI specification consists of four bytes (0xFF 0xFF 0xFF 0x7F), representing a 28-bit integer with a maximum value of 268,435,455 ticks.

Converting Ticks to Real Time

A delta-time value does not inherently define seconds or milliseconds; it strictly denotes abstract sequencer "ticks." To convert delta-ticks into physical wall-clock time, a MIDI parser references two parameters:

  1. Division (Time Base): Stored in the file’s header chunk (MThd), this 16-bit integer defines the resolution of the sequence, most commonly expressed as Pulses Per Quarter Note (PPQN). A common PPQN setting is 480 or 960 ticks per quarter note.
  2. Tempo: Defined by a Meta Event (FF 51 03) within the track chunk, tempo is expressed as microseconds per quarter note. The default tempo is 500,000 microseconds per quarter note (equivalent to 120 beats per minute).

The physical time duration represented by a delta-time is calculated using the formula:

\[\text{Time (seconds)} = \text{Delta-Ticks} \times \left( \frac{\text{Microseconds per Quarter Note}}{\text{PPQN} \times 1,000,000} \right)\]

Whenever a tempo meta-event occurs, the real-world duration of subsequent delta-ticks adjusts accordingly, while the relative tick count remains constant.

Track Traversal and End of Track

Because delta-times directly prefix every MIDI message, an MTrk chunk cannot be parsed by simply searching for status bytes. The parser must always read the delta-time first, advance its internal playback clock by that number of ticks, and then read and execute the MIDI or Meta event that follows. This cycle repeats until the parser encounters the mandatory End of Track meta-event (FF 2F 00), which also carries its own delta-time to ensure any trailing silence at the end of the musical piece is preserved.
