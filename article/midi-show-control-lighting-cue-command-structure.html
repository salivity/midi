MIDI Show Control Lighting Cue Command Structure

MIDI Show Control (MSC) uses specialized MIDI System Exclusive (SysEx) messages to automate and synchronize entertainment control systems. In lighting environments, an MSC cue command provides a standardized communication protocol that instructs a lighting console to execute, stop, or modify cues. Understanding the structural parameters of an MSC lighting command requires examining the standard SysEx framing, the specific lighting command format designator, the control command type, and the optional cue payload parameters.

System Exclusive Framing

Every MSC lighting command is encapsulated inside a standard MIDI Universal Real-Time System Exclusive message. The initial bytes establish the message protocol and target device:

  • SysEx Start Byte (F0): Initiates the MIDI System Exclusive transmission.
  • Universal Real-Time Header (7F): Identifies the message as a Real-Time Universal System Exclusive transmission.
  • Device ID: A 7-bit value (00 to 7F) indicating the target receiver. A value of 7F acts as an all-call or broadcast address, instructing all connected MSC-compatible devices to interpret the command.
  • MSC Sub-ID #1 (02): Defines the message specifically as a MIDI Show Control command.

Command Format (Device Category)

Following the MSC header is the Command Format byte, also known as MSC Sub-ID #2. This byte establishes the class of equipment being addressed.

For lighting systems, the standard Command Format byte is 01 (General Lighting). This parameter ensures that sound, video, or pyrotechnic controllers ignore the instruction, routing the command strictly to designated lighting consoles or dimmer racks.

Command Byte

The Command byte determines the action the lighting controller must take. Standard MSC command bytes include:

  • 01 (GO): Starts a crossfade to the specified cue. If no cue parameters are supplied, it initiates the next sequential cue.
  • 02 (STOP): Pauses or halts the current cue transition.
  • 03 (RESUME): Resumes execution of a halted cue.
  • 04 (TIMED_GO): Triggers a crossfade to a specific cue over a predetermined time duration provided within the command payload.
  • 0B (FIRE): Fires an assigned lighting macro.

Data Field Parameters

When a command targets a specific lighting state rather than triggering a generic action, an optional payload containing ASCII-encoded data follows the Command byte. The payload contains up to three delimited fields:

  1. Cue Number: The primary target cue, represented as an ASCII character string (e.g., ASCII characters for "1", "0", ".", "5" to specify Cue 10.5).
  2. Delimiter (00): A null byte separating the cue number from subsequent parameters.
  3. Cue List: An optional ASCII string specifying which cue stack or fader contains the cue (e.g., Cue List "2").
  4. Delimiter (00): A null byte separating the cue list from the cue path.
  5. Cue Path: An optional ASCII string indicating a specific memory path or directory structure from which the cue should be drawn.

If a specific cue number is targeted without specifying a cue list or path, the message does not require trailing delimiters.

Termination Byte

  • End of Exclusive (F7): Marks the formal completion of the System Exclusive data packet. Once received, the target lighting console processes and executes the framed command.
