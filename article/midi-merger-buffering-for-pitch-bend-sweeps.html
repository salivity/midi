MIDI Merger Buffering for Pitch Bend Sweeps

When two dense MIDI pitch bend sweeps arrive simultaneously at a MIDI merger, the aggregate input bandwidth exceeds the standard MIDI 1.0 transmission rate of 31.25 kbaud. To prevent buffer overflow, introduced latency, and data corruption, a hardware or software MIDI merger cannot rely on a naive first-in, first-out (FIFO) queue. Instead, it must implement an intelligent buffering strategy combining independent input ring buffers, complete message-level interleaving, running status reconstruction, and dynamic state-based event decimation (thinning).

The Bandwidth Bottleneck

A standard MIDI 1.0 serial connection operates at 31.25 kbaud, allowing roughly 1,041 three-byte messages per second. A single dense pitch bend sweep can easily saturate 50% to 80% of this capacity. When two input streams simultaneously transmit high-density pitch bend messages (Status Byte 0xE0–0xEF followed by two 7-bit data bytes representing the 14-bit pitch value), the combined throughput demands up to 160% or more of the single output port’s physical capacity.

A standard FIFO buffer will immediately fill, causing either a memory overflow crash, unrecoverable packet loss, or a continuously expanding latency queue that leaves pitch bends lagging seconds behind the performance.

Independent Input Circular Buffers

The initial stage requires dedicated, interrupt-driven circular (ring) buffers for each physical UART input.

  • Atomic Writes: Incoming bytes must be captured immediately via hardware interrupts and written into distinct input queues without blocking.
  • Packet Framing: The merger's parser must delineate individual MIDI messages within these input buffers before passing them to the merge engine. Pitch bend messages must be recognized as atomic, 3-byte units.

Complete Message Interleaving

MIDI status bytes and data bytes cannot be interleaved at the byte level without corrupting the data stream. The scheduler must pull full 3-byte pitch bend messages from each input buffer alternately (e.g., using a weighted round-robin scheduler).

Furthermore, MIDI Running Status—where subsequent data bytes omit the status byte if it matches the previous message—must be explicitly managed:

  • The merger must unpack running status data at the input buffers to reconstruct explicit 3-byte messages.
  • When interleaving alternate streams to the output port, the merger must either dynamically insert the appropriate status byte whenever the stream source changes or selectively re-encode running status on the output line.

State-Based Thinning and Decimation

Because pitch bend is an absolute controller value rather than a transient trigger (like Note On or Note Off), intermediate pitch bend values carry no persistent musical state. The most critical buffering strategy for handling simultaneous dense sweeps is intelligent event decimation:

  1. Queue Watermarking: The merger monitors the fill level of the outbound transmission buffer. When occupancy crosses a predetermined threshold (e.g., 70%), decimation routines activate.
  2. Channel-Specific Coalescing: If multiple pitch bend messages for the same MIDI channel reside in the queue, the merger drops intermediate values, retaining only the most recent pitch bend value.
  3. Decimation Scaling: If the sweep is directed at different MIDI channels (e.g., Input 1 on Channel 1 and Input 2 on Channel 2), the engine drops alternating intermediate bend values from both streams. For example, if a buffer holds values [64, 68, 72, 76], decimation can safely reduce this to [64, 76] or calculate an evenly spaced subset without altering the final destination pitch.

Latency Bounding

To maintain real-time musical performance, the merger must enforce a hard upper bound on output buffer latency, typically under 5 milliseconds. If the output buffer latency approaches this threshold due to sustained simultaneous sweeps, the decimation engine aggressively flushes older un-transmitted pitch bend messages from the queue. This preserves instantaneous timing at the expense of step resolution, ensuring the synthesizer hardware receives the current pitch targets without audible lag.
