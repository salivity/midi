macOS Audio MIDI Setup Physical and Virtual Routing

The macOS Audio MIDI Setup utility provides a centralized, graphical environment known as the MIDI Studio to visualize, configure, and route both hardware and software MIDI streams across the operating system. This article examines how the utility depicts physical hardware connections via virtual cabling, manages inter-application routing through the Inter-Application Communication (IAC) Driver, and bridges local network and wireless devices through dedicated virtual nodes.

The MIDI Studio Interface

The MIDI Studio window functions as a dynamic canvas that reflects CoreMIDI's internal configuration. Every active MIDI endpoint connected to macOS is visually rendered as a distinct device icon. Each device block displays input and output connection terminals (represented by directional arrowheads), which indicate the number of physical or logical ports available for that specific endpoint.

Visualizing Physical Hardware Connections

When class-compliant USB MIDI controllers or multi-port MIDI interfaces are plugged into the Mac, Audio MIDI Setup automatically generates an icon representing that hardware. However, traditional hardware instruments connected via standard 5-pin DIN cables do not automatically report their presence to the system.

To map traditional hardware:

  1. Users create a placeholder icon using the "Add Device" function.
  2. The user configures properties such as device name, manufacturer, and active MIDI channels.
  3. The user creates a visual connection by clicking a port terminal on the interface icon and dragging a virtual patch cord to the corresponding input or output terminal on the external gear icon.

This virtual patch cord represents the physical MIDI cable layout in the studio. CoreMIDI uses this visual mapping to broadcast port names and channel assignments directly to digital audio workstations (DAWs) and standalone software instruments.

Virtual Inter-Application Routing (The IAC Driver)

To route MIDI data between two software applications running on the same Mac—such as sending clock from a DAW to a standalone sequencer—Audio MIDI Setup provides the Inter-Application Communication (IAC) Driver.

Unlike physical devices, the IAC Driver exists entirely within software:

  • Activation: The IAC Driver icon appears permanently inside the MIDI Studio canvas. It is inactive by default and must be set to "Device is online" inside its property inspector.
  • Buses: Users can configure one or more virtual "buses" (named channels).
  • Application Access: Each active bus manifests inside any CoreMIDI-compatible application as an independent input and output destination.

Once configured, data sent to an IAC output port by one program is immediately available on that same IAC input port in another program, removing the need for external loopback cables or third-party virtual routing utilities.

Network and Wireless Virtual Endpoints

Audio MIDI Setup also handles remote inter-device communication via RTP MIDI and Bluetooth:

  • Network Sessions: Accessed via the Network icon, this creates software-based network endpoints that route MIDI over local Wi-Fi or Ethernet. It allows bi-directional communication with other Macs, iOS devices, or Windows computers using the Apple MIDI network protocol.
  • Bluetooth MIDI: The Bluetooth panel scans for and connects to low-energy wireless controllers, instantly instantiating them as standard device nodes within the canvas.

Both network sessions and Bluetooth connections are represented in the CoreMIDI environment as standard routing endpoints, functioning identically to local hardware ports or IAC virtual buses.
