How Button Debouncing Stops Rapid MIDI Note On Events

When a mechanical button is pressed, its physical contacts rapidly bounce against each other, creating dozens of transient electrical connections within a few milliseconds. To an unfiltered microcontroller checking pin states at thousands of cycles per second, this erratic voltage fluctuation appears as multiple rapid button presses, causing it to transmit a rapid-fire cascade of unintended MIDI Note On messages known as the "machine-gun" effect. Button debouncing code resolves this issue by introducing software-based timing filters and state validation routines, ensuring that only a single, deliberate press is processed and translated into a single MIDI event.

The Physics of Contact Bounce

Mechanical switches rely on conductive metal contacts that collide to complete a circuit. At a microscopic scale, these metal leaves act like springs. When pressed, they do not make instant, continuous contact; instead, they bounce against each other for anywhere from 1 to 20 milliseconds before settling into a closed state.

Because microcontrollers execute code in microseconds, a loop polling a digital input pin will detect every single bounce as an alternating sequence of HIGH and LOW logic levels. If the program simply maps a LOW-to-HIGH transition directly to a MIDI output function, the microcontroller sends a new MIDI Note On command (0x90) with every single microscopic bounce. In a digital audio workstation (DAW) or synthesizer, this overwhelms the MIDI buffer, causes voice-stealing artifacts, and produces an aggressive stutter instead of a clean musical note.

Software Debouncing Techniques

Debouncing code prevents this behavior by ignoring subsequent electrical transitions until the mechanical switch has stabilized. Microcontrollers achieve this through several primary software patterns:

1. Non-Blocking Time Lockouts (Deadband Timing)

The most common approach utilizes a system timer (such as millis() or micros() on an Arduino or ARM-based board). When the microcontroller detects the initial edge of a button press:

  1. It immediately transmits the MIDI Note On message, ensuring zero perceived latency for the musician.
  2. It records the current timestamp.
  3. It enters an intentional "lockout" state for a defined debounce window—typically 10 to 30 milliseconds.
  4. Any state changes occurring on the input pin during this lockout window are discarded.
  5. Once the timer expires, the microcontroller resumes listening for legitimate state changes (such as a button release).

2. Consecutive State Sampling

Another method avoids reacting to the very first transition edge. Instead, the microcontroller samples the pin at fixed intervals (e.g., every 2 milliseconds). The code maintains a counter:

  • If the switch reads HIGH, the counter increments.
  • If the switch reads LOW, the counter resets to zero.

Only when the counter reaches a predetermined threshold—proving the pin has remained steadily HIGH across multiple consecutive readings—does the program register a valid press and transmit the MIDI Note On command. While this adds a tiny delay (usually imperceptible under 5 milliseconds), it eliminates false triggers caused by electromagnetic interference or static spikes.

3. Bitmask Filtering (Shift Registers)

For microcontrollers handling high-density MIDI control surfaces with dozens of buttons, developers often use bit-shift operations. Every millisecond, the program reads the physical pin and shifts that binary value (0 or 1) into a single 8-bit integer:

history = (history << 1) | readPin();

The code checks whether the 8-bit integer matches a stable pattern. For example, 0b11111111 confirms that the button has been held down consistently for eight consecutive checks, while 0b00000000 confirms a stable release. A MIDI Note On is dispatched exclusively on the exact cycle the variable transitions from containing non-uniform bits to eight consecutive ones.

Debouncing the Note Off Event

Debouncing is not only necessary when a button is pressed; it must also be applied when the button is released. As the internal spring pulls the contacts apart, the switch bounces again on separation. Without release debouncing, a single release could trigger momentary contact reconnects, generating accidental secondary Note On events right as the musician intends to silence the note. Applying debouncing bidirectionally ensures clean MIDI Note Off commands (0x80 or Note On with velocity 0) and maintains predictable voice allocation on the receiving synthesizer.
