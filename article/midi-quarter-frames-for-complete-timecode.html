MIDI Quarter Frames for Complete Timecode

MIDI Time Code (MTC) uses Quarter Frame messages to synchronize digital audio workstations, lighting consoles, and video hardware efficiently without overloading the MIDI bandwidth. This article explains the structure of MTC Quarter Frame messages and reveals the exact number of consecutive messages required to rebuild a complete timecode frame count.

To rebuild a complete timecode frame count, exactly 8 consecutive MIDI Quarter Frame messages are required.

MIDI Time Code breaks standard SMPTE timecode (Hours:Minutes:Seconds:Frames) into 4-bit nibbles. Because MIDI messages prioritize low data bandwidth, transmitting an entire 32-bit timecode value at once would consume too much bandwidth during continuous playback. Instead, MTC distributes this data across eight separate Quarter Frame messages.

Quarter Frame Structure

Each Quarter Frame message consists of a two-byte sequence:

  1. Status Byte: 0xF1 (MIDI Time Code Quarter Frame indicator)
  2. Data Byte: An 8-bit byte where the upper nibble (3 bits used, 1 bit zero) identifies the piece of timecode, and the lower nibble (4 bits) contains the actual timecode data.

The eight distinct messages are indexed from 0 to 7:

  • Message 0: Frame count, least significant nibble
  • Message 1: Frame count, most significant nibble
  • Message 2: Seconds count, least significant nibble
  • Message 3: Seconds count, most significant nibble
  • Message 4: Minutes count, least significant nibble
  • Message 5: Minutes count, most significant nibble
  • Message 6: Hours count, least significant nibble
  • Message 7: Hours count, most significant nibble (combined with SMPTE frame rate type)

Transmission and Timing

Quarter Frame messages are transmitted at a rate of four messages per timecode frame. Because it requires 8 consecutive messages to transmit all the nibbles for hours, minutes, seconds, and frames, a receiver requires the span of two complete frames to reconstruct a full timecode reading.

Once message 7 is successfully received, the receiving device has the complete, updated SMPTE timecode count and sets its internal clock to the time represented, factoring in the two-frame offset accumulated during reception.
